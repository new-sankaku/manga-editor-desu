# V3 原稿の画面（`v3/web/manuscript/`）

ページの上でコマ枠・文字とフキダシ・トーン・層・コマの絵を扱い、ページを並べ、入稿前に確かめる画面。
1つのコマの絵を AI に頼むのは画像生成の画面（`v3/web/index.html`、`V3画像生成の機能と画面.md`）で、ここからはリンクで渡す。

## 1. 動かし方

- サーバー（`V3サーバーの土台.md`）を起動すると、`/web/manuscript/index.html` で出る。サーバーと同じ口から出すので `file://` の制約はかからない。
- 開くページは URL で決める：`manuscript/index.html?work=<作品>&page=<ページ>`。`&episode=<話>` は page が無いときだけ使う。どれも無ければ、画面の帯（`common/nav.js`）が覚えた作品と、前に開いたページを出す。選び直すと URL も替える（`history.replaceState`）。
- 試験：`v3/web/test/manuscript_ui.mjs`（Playwright）。Chromium は `/opt/pw-browsers` のものを使う。
  - 本物のサーバー：`V3_ORIGIN=http://127.0.0.1:<口> SHOTS=<絵を置く所> NODE_PATH=/opt/node22/lib/node_modules PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node v3/web/test/manuscript_ui.mjs`。サーバーは `V3_AUTH_MODE=dev_header` で動かす。
  - 偽のサーバー：`MOCK=1`（`test/manuscript_mock_server.mjs`）。判断待ちを作れるのはこちらだけ（本物では AI の操作が要る）。
  - 試験の作品は `test/manuscript_seed.mjs` が作る：B5（仕上がり 182×257mm・枠 150×220mm・裁ち落とし 3mm）、600dpi、右から読む・縦書き、4ページ（1ページ目にコマ 6・フキダシ 10（うち1つはつないだもの）・トーン 3（網点・グラデ・集中線）・コマの絵 2、3・4ページは見開き）。
- 画面の絵：`v3/web/manuscript/screenshots/`（01 コマとフキダシ、02・03 ナイフ、04 縦書きをその場で打つ、05 判断待ち（偽のサーバー）、06・07 見開き、08・09 ページの一覧、10 入稿前の確かめ）。05 のほかは本物のサーバーで撮った。

## 2. ファイル

| ファイル | 中身 |
|---|---|
| `index.html` | 上に作品・話・ページと見開き、画面の帯（`common/nav.css`・`nav.js`）。真ん中に道具の帯とページ、下にページの一覧、右に「判断」「道具」「層」「確かめ」のタブ |
| `css/manuscript.css` | 配置と部品。色は `common/theme.css` の色の組だけを使う |
| `js/main.js` | 状態・読み込み・選ぶ・変える（`change`）・取り消し・キー |
| `js/page_view.js` | ページを描く（Fabric.js 7.4.0）。拡大と移動、コマ枠・ナイフ・フキダシ・しっぽ・トーン・絵・印 |
| `js/text_layer.js` | 文字（HTML の要素。縦書きは CSS の `writing-mode`）とその場で打つ所、人の手と判断待ちの印 |
| `js/tone_draw.js` | トーンを canvas に描く（画面で見るため。書き出しはサーバー） |
| `js/panes.js` | 右のタブと下のページの一覧（並べ替えは SortableJS 1.15.6、`vendor/sortablejs-1.15.6/`） |
| `js/model.js` | 正本（`GET /works/{id}`）を持ち、送る前の操作を手元に当てる |
| `js/saver.js` | 操作を1つずつ送る。失敗したら止めて、画面に出す |
| `js/geometry.js` | 多角形・ナイフの線・フキダシの形 |
| `js/theme_colors.js` | canvas に塗る画面の色を `common/theme.css` から読む（`getComputedStyle`）。原稿の画面で色を読むのはここだけ |
| `js/print_colors.js` | 原稿のデータとしての色（新しいフキダシの線の黒・塗りの白・文字の黒）。書き出しに入る色で、色の組ではない |
| `js/ui.js` | 小さな部品（欄・ボタン・知らせ） |

React は使わない。ライブラリは手元に置く（Fabric.js・Lucide・SortableJS）。

## 3. できること

- ページ：1ページか見開き（読む向きに合わせて右・左に置く。見開きの組のページはノドで付けて並べる）。Ctrl を押したホイールで拡大（トラックパッドのつまむ動きも同じ）、ホイールで移動。拡大中は CSS で動かし、止まってから描き直す。
- コマ枠：作る（ドラッグ）、ナイフで分ける（横・縦・斜め。線を見てから押す。間はコマの間の設定）、動かす・大きさ・頂点、間と線の太さ・色、作品の標準の線。
- 文字とフキダシ：作る（作るとすぐ打てる）、2回押すとその場で打つ（縦書きをそのまま見る。数字と `!?` は縦中横）、向き・大きさ・書体・不透明度・文字の色、組版（作品の標準か、文字ごと）、フキダシの形（楕円・角丸・叫びなどの型から作り直す）・線・塗り・しっぽ（先・付け根の幅・曲がり・外す）・前のフキダシとつなぐ。
- トーン：作る（網点・線・砂・雪・グラデ・集中線・流線）、濃さ・角度など。
- 層：見せる・動かさない（種類ごと）、ページの物とコマの層の順・見せる・不透明度・固定。
- コマの絵：置く（ファイルを上げる。出どころ・利用の条件）、動かす・大きさ。「このコマの絵を頼む」で画像生成の画面へ（`../index.html?work=&page=&panel=`、キー L）。
- ページの一覧：ドラッグで並べ替え（見開きの組が離れる並べ方は送らずに戻す。サーバーも同じ理由で断る）、種類・色・解像度・ノンブル、ページを足す・抜く、見開きにする・解く、1ページ目を右か左か。
- 入稿前の確かめ：このページか話の全部をサーバーの `preflight` に送り、ページごとに並べる。場所のある問題を押すとそこへ飛んで選ぶ（右のタブは確かめのまま）。
- 判断待ち（`held-changes`）：一覧と、ページの上の印（「判断 n」）。J・K で選び、A で受け入れ、X で断る。
- 人の手の印：人が変えた所に「手」を出す（層のタブで隠せる）。

### 3.1 保存と取り消し

- 変更は全部サーバーの操作（`POST /works/{id}/ops`）で送る。先に画面に当て（手元の `model.js`）、後ろで1つずつ送る。
- 送るのに失敗したら、それ以降は送らずに止め、上に「保存できませんでした」と理由を出す。「もう一度送る」か「この変更を捨てる」（読み直す）を選ぶ。止まっている間は新しい変更を受けない。黙って捨てない。
- 取り消し・やり直しはページごと（Ctrl+Z・Ctrl+Shift+Z・Ctrl+Y）。取り消しは `POST /works/{id}/events/{eid}/undo`、やり直しは取り消しの出来事をもう一度取り消す。
- 閉じるときに送っていない変更があれば止める（`beforeunload`）。

### 3.2 キー（決めごと 22.2）

V 選ぶ・F コマ枠・C ナイフ・S フキダシ・T 文字・N トーン・H 手のひら（Space を押している間も）・L 絵を頼む・D 右のタブを順に・W 層・J/K 判断待ち・A/X 受け入れる/断る・+ − 0 拡大・PageUp/PageDown ページ・Delete 抜く・? キーの一覧。R・B・E・U・O・Q はまだこの画面に無い（押すと知らせる）。

### 3.3 色の組

- 画面の色は `common/theme.css` の色の組だけを使う。CSS は `var(--…)`、canvas（Fabric）は `js/theme_colors.js` が `getComputedStyle` で1か所で読む。色の組を差し替えたら `PageView.retheme()` で読み直す（差し替える仕組みはまだ無い）。
- 使う名前：`--ai`・`--ai-line`・`--need`・`--bad-line`・`--on`。紙の上（紙・裁ち落としの外・紙の縁・文字）は `.paper` の組の `--surface`・`--bg`・`--line-2`・`--ink`。
- 原稿のデータとしての色（フキダシの線の黒・塗りの白・文字の黒）は `js/print_colors.js` に分けた。色の組を替えても刷る色は変わらない。
- 画面の文字は `.paper` の `--ink`（#2B2822）で見せる。刷る黒（#000000）とは少し違う。文字の色（`decoration.fill`）を画面にも当てるので、決まっている文字はその色で見える。

## 4. 測った数（2026-10-08）

B5 600dpi・コマ 6・フキダシ 10・トーン 3・コマの絵 2（1720×1420 と 3540×1750 画素）。画面 1440×900。この機械（コンテナの中の Chromium、GPU なし）。

| | 本物のサーバー | 偽のサーバー |
|---|---|---|
| フキダシを 60 回に分けてドラッグ：Fabric の描画 p50 / p95 / 最大 | 3.2 / 9.6 / 21.8 ms | 3.0 / 5.9 / 14.3 ms |
| 同じドラッグ中のフレームの間 p50 / p95 | 16.7 / 16.8 ms（別の回は 33.3） | 16.7 / 33.4 ms |
| ドラッグを離してから正本に入るまで（送る〜返る） | 113 ms（画面の操作から 189 ms） | 94 ms |
| 保存 10 回（文字の大きさを変える）p50 / 最大 | 152 / 196 ms | 125 / 166 ms |
| Ctrl+ホイール 20 回の間の描き直し | 1 回（1.84 倍 → 36.96 倍） | 1 回 |

- フレームの間 p95 は回によって 16.8 ms と 33.3 ms の間で揺れる（3回測った）。
- 偽のサーバーはブラウザの中で返すので、保存の数は画面の側の時間に近い。

## 5. 未検証

- 画面の縦書き（ブラウザの CSS）とサーバーの組版（`v3/psd_writer/text_layout.js`：HarfBuzz・UAX #14・BudouX）が同じ所で改行するか。サーバーの組版をその場で呼ぶ口は無く、確かめ（`preflight` の text_overflow・font）でだけ分かる。
- 画面の書体：ブラウザは作品の書体（例：IPAMincho）を持たないと別の書体で見せる。書体を配る口が無い。
- しっぽの形：画面の描き方（付け根の幅と曲がり）が書き出しと同じ形になるか。
- トーンの見た目：画面のトーンは見るためのもので、書き出しの網点と線数・角度が合うか。
- 拡大を止めてからの描き直し（140 ms 待つ）が、大きなページ（絵の多いページ）でも速いか。測ったのは上の1ページだけ。
- GPU のある機械・ペンタブレットでの速さと、タッチ画面の2本指での拡大（Ctrl 付きのホイールしか受けていない）。

## 6. まだ作っていないもの

- キー R（赤入れ）・B（ペン）・E（消しゴム）・U（図形）・O（読む順）・Q（順番待ち）と、G での画面の切り替え。ペンと消しゴムは画像生成の画面にある。
- 文字の一部の書式（`spans`）とルビを打つ所（打ち直すと外す）。文字の飾り（縁・影など）を変える所（見せるだけ）。
- 図形、マスクを対象にするトーン、見開きにまたがる絵を動かすこと、閾値を決める所（ナイフに要る `panel_short_side_min_mm` が無いと、ナイフのタブで知らせるだけ）。
- 色の組を差し替える仕組み（読み直す所だけある）。

## 7. サーバーで見つけたこと

- **ナイフで分けた小さい側に文字が入ると 500 を返す**（v3-server-plan、`v3/server/src/v3server/operations/panel_frame_operations.py` の `SplitPanel.apply` と `_Plan.apply`）。`_Plan.apply` は変更（文字の `panel_id` を新しいコマへ）を先に当て、新しいコマの行は最後に `session.add` する。その間に読み込みが起きると先に UPDATE が流れ、`text_items_panel_id_fkey` に反する。`_Plan.apply` で `creates` を `changes` より先に置けば直る見込み（未検証。サーバーは直していない）。画面は失敗を出して止まる（正しい振る舞い）。試験は文字の入らない所で分けている。
- 文字の色（`decoration.fill`）が無い文字は、書き出しも確かめも止まる。画面は作る文字に黒を入れ、文字の欄に「未設定（書き出しで止まります）」を出す。

## 8. 偽のサーバーの限り

- 出来事を当て直して状態を作る（取り消していない出来事だけ）。サーバーの決まり（人の手の印・AI の扱い・ロック・権限・閾値の値の検査）は持たない。ナイフの分け方は画面と同じ `geometry.js` を使うので、サーバーとの食い違いは見つけられない。
- 確かめは安全な範囲・空の文字・絵の解像度・判断待ちだけ。
- 判断待ちは試験が直接置く。
