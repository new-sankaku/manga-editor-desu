# 監査3：画面と使い勝手（v3/web と試作・決めごとの差）

対象：ブランチ v3-server-plan、HEAD 6026d6c。コードと文書は変えていません。

## 0. 測り方

- v3/server を別のデータベース（v3audit、終了後に消しました）と口 8793 で起動し、Playwright（/opt/pw-browsers の Chromium、ヘッドレス）で `/web/` を開きました。uvicorn は止めました。
- 絵は B5・600dpi 相当の 4960×7016 の白黒 PNG（1.3MB、線 3,000 本と網点）。作品・ページ・コマを作り、`image_placement` を 182×257mm に置きました。
- ComfyUI は動かしていないので、生成そのものと候補の表示は測っていません。候補に重ねる橙の絵の処理（`maskOverlay`）は、消しゴムで作った人の手の範囲で単独に測りました。
- ヘッドレスは GPU を使わないので、絶対の時間は実機より遅い可能性があります。ただし下の遅さは、どれも「動かすたびに絵の全画素を触る」作りから来ており、画素数に比例する点は実機でも同じです。
- 画面の写し：`audit/narrow_390.png`（幅 390px）。

## 2. v3/web の質（プロの漫画家が毎日使う道具として）

### 2.1 ペンタブレットの筆圧とポインタの出来事
- **分類：足りない／重さ：必須**
- fabric 7.4.0 の `enablePointerEvents` の既定は false（vendor/fabric-7.4.0/fabric.min.js の既定値 `enablePointerEvents:!1`）。stage.js:17 で入れていないので、届くのは `MouseEvent` です（実測：`ctor: MouseEvent`）。筆圧・傾き・`pointerType`・`getCoalescedEvents` は取れません。
- stage.js:347 は筆圧が無いと 0.5 を入れます。実測で保存された点はすべて 0.5 でした。これは CLAUDE.md の「fallback禁止」に当たり、さらに作った値を正本（`add_pen_strokes` の点）に残しています。後で筆圧で描き直す仕組みを作っても、それまでの線はすべて筆圧 0.5 の偽のデータになります。
- 見本の線も、確定した控えも太さが一定です（stage.js:374、app.js:625）。入り抜きの無い線は、漫画のペン入れには使えません。
- 指で2本の拡大・回転、手のひら（タッチ）とペンの区別、手を置いたときの誤入力の除外もありません。

### 2.2 描くときの遅れ
- **分類：高度化が要る／重さ：必須**
- 囲む筆は、マウスが動くたびに `maskChanged()`（stage.js:157-162）を呼び、その中で `subtractProtected()`（全画素の合成）と `hasMask()`（stage.js:185-190、`getImageData` で全画素を読む。実測 98 ms）を走らせます。さらに fabric に全画素の canvas を描き直させます（`objectCaching:false`、stage.js:70）。実測で1回の移動が中央値 215 ms、線1本（40回の移動）に 10.2 秒かかりました。筆が手から 0.2 秒遅れて付いてくる道具は、囲む用途でも使えません。
- `hasMask()` の結果を受け取る `onMaskChange` は空の関数です（app.js:742）。全画素を読む処理が、何にも使われずに毎回走っています。
- ペンは離した後に、操作 2 回・作品全体の読み直し 3 回・線の控えの全画素の描き直しと PNG 化（実測 560 ms・6.2 MB）・上げる・コマの絵の読み直し・版の読み直しを順に待ちます（app.js:637-660）。1 本ごとに約 1.5 秒、線が確定するまで次の線の結果が見えません。見本の線も、動くたびに点の並び全体から図形を作り直しています（stage.js:372-374）。
- 消しゴムは 1 本で 7.5 秒でした（`afterChange` で作品・コマの絵・人の手の範囲・候補・版を全部読み直し、橙の絵を全画素で作り直す。app.js:662-672、api.js:71-86）。

### 2.3 600dpi・1200dpi での拡大・移動とメモリ
- **分類：高度化が要る／重さ：必須**
- 囲みの1つ戻すは、全画素の `ImageData`（4960×7016 で 139 MB）を 30 回まで溜めます（stage.js:9, 134-138）。実測で線 13 本でヒープが 1,863 MB になりました。30 本で約 4.2 GB になり、タブが落ちる大きさです。1200dpi（9920×14032）なら 1 回が 557 MB で、2〜3 本で落ちます。差分（線の範囲だけ）か、線の記録で持つ作りが要ります。
- 囲みの反転 709 ms、送るマスクの PNG 化 862 ms（stage.js:172-183, 193-202）も全画素の JS ループです。
- 絵の表示は fabric に1枚の絵として渡すだけで、縮小版（ミップマップ）や分割の仕組みはありません。拡大は最大 32 倍（stage.js:99, 286）。描画自体は速かった（全体表示 3.5 ms）ですが、1200dpi では GPU の1枚の大きさの上限（多くの環境で 16384px）に近づきます。未検証です。
- `blobUrl` で作った blob の URL を一度も解放しません（api.js:50-61。`revokeObjectURL` がどこにも無い）。版を見る・比べるたびに、全画素の絵がメモリに残り続けます。形の指定の絵も同じです（app.js:291）。
- 正本の作品全体（全コマ・全層・全ペンの線）を、操作のたびに `GET /works/{id}` で読み直します（app.js:117-119, 500-505, 647, 656）。ペンの線の控えは、その層の全部の線から毎回描き直します（app.js:613-635）。1 話 200 ページ・線数万本になると、1 本描くごとに作品全体を 3 回読み、全線を描き直すことになります。

### 2.4 拡大・移動の操作
- **分類：磨けていない／重さ：重要**
- ホイールは Ctrl なしで拡大になります（stage.js:284-288。実測で普通のホイールで倍率が変わった）。トラックパッドの2本指で動かせません。`deltaMode` を見ていないので、行単位でホイールを送る環境では拡大の量が変わります。
- スペースを押している間の手のひらがありません（実測：動かない）。`+`・`-`（§22.2）も効きません（実測）。100% 表示・倍率の数字・倍率を打ち込む欄もありません。
- 道具を替えるたびに `fit()` を呼ぶので（stage.js:115）、拡大して細部を囲んでいる途中でペンに替えると、全体表示に戻されます。

### 2.5 ショートカットキーと変更
- **分類：足りない／重さ：重要**
- 割り当ては V・M・O・P・E・Ctrl+Z・Ctrl+Shift+Z だけです（app.js:723-732）。§22.2 では、囲んで頼むは L、ペンは B、O は読む順です。決めた割り当てと違うので、全画面を作るときに付け替えが要ります。
- 筆の太さ（`[`・`]`）、囲みの足す・引く、1つ戻す（囲み）、`?` のキーの一覧、`/`、J/K/A/X/1〜6 がありません。割り当てを変える設定もありません（§22.1）。
- キーを受け取る所が stage.js:299-303 と app.js:723-732 の2か所に分かれています。§22.1「1か所で押す」に合っていません。

### 2.6 取り消し
- **分類：磨けていない／重さ：必須**
- 取り消しが2つの別の仕組みです。囲みは画面の中だけの「1つ戻す」ボタン（キー無し）、ほかはサーバーの出来事の取り消し（Ctrl+Z）です。囲む道具を使っている最中に Ctrl+Z を押しても、囲みは戻りません（実測：戻す前後で囲みの記録の数が 14 のまま）。前に行った採用やペンの線が、見えていない所で取り消されます。
- 取り消しの積み上げは作品を替えたときだけ空にし（app.js:81）、コマを替えても残ります（app.js:106-115）。コマ B を見ながら Ctrl+Z を押すと、コマ A の採用が画面に出ないまま戻ります。
- 積み上げは画面のメモリだけで、読み直すと消えます。サーバーには出来事の一覧（`/works/{id}/events`）があるのに使っていません。
- 消しゴムを使うとコマの絵の id が変わり、塗っていた囲みが知らせなしに消えます（stage.js:64-69。実測でヒープが 1,996 MB から 137 MB に戻り、囲みが消えた）。

### 2.7 囲む道具（マスク）
- **分類：足りない／重さ：重要**
- 筆の硬さ・不透明度・ぼかしがありません。筆はいつも硬い丸です（stage.js:204-212）。サーバーで縁をぼかしていても、その結果を画面で前もって見る仕組みはありません。
- 投げ縄・多角形・四角はいつも「足す」です（stage.js:385-394, 402-407）。Shift／Alt での足す・引く・重なりだけ、が無く、引くには「消す」の筆に持ち替えるしかありません。
- クイックマスク（囲みを赤い膜で見せて筆で直す）、色で選ぶ（自動選択）、囲みを広げる・縮める、線画の閉じた所を塗る（漫画では最も多い選び方）がありません。
- 筆の太さの上限 200px（index.html:46）は、600dpi では 8.5mm です。背景を広く囲むには細すぎます。太さは絵の画素で決まるので、拡大の倍率によって画面での太さが変わります。

### 2.8 色を拾う
- **分類：足りない／重さ：後で**（白黒の原稿では優先は低い）
- ペンの色は黒に固定です（app.js:645）。スポイト・色の選択はありません。

### 2.9 ナビゲーター
- **分類：足りない／重さ：重要**
- 全体の小さい図と、今見ている範囲の枠がありません。600dpi で 400% 以上に拡大すると、どこを見ているか分からなくなります。

### 2.10 定規・ガイド・吸着
- **分類：足りない／重さ：後で**（コマ単位の生成画面では。原稿の画面では必須）
- 定規・ガイド・吸着・パース定規はありません。四角の囲みにも吸着がありません。

### 2.11 キャンバスの回転・左右反転表示
- **分類：足りない／重さ：重要**
- 表示の回転・左右反転がありません。手描きの線を引くとき、描く人は紙を回します。左右反転の表示は絵の狂いを見るためにプロが常に使います。さらに、置き場に回転があるとペンと mm の換算を止めます（app.js:57-60, 189）。

### 2.12 左利き・機器の設定
- **分類：足りない／重さ：後で**
- 左利き向けの配置、ペンの筆圧の曲線、ペンのボタンの割り当て、タッチを切る設定がありません。設定の画面そのものがありません。

### 2.13 自動保存と戻し
- **分類：磨けていない／重さ：重要**
- 採用・ペン・消しゴムは操作のたびにサーバーに残ります（良い）。
- 塗っていた囲み・入力欄の文（指示）・枚数・種は画面のメモリだけです。読み直し・コマの切り替え・消しゴムで消えます（2.6）。`beforeunload` の確かめもありません。数分かけて囲んだ範囲を、操作1つで失います。

### 2.14 失敗・オフライン
- **分類：磨けていない／重さ：重要**
- 失敗はトーストに例外の文をそのまま出します（app.js:39）。オフラインでは「Failed to fetch」と英語で出ました（実測）。何を頼んで失敗したか、送られたかどうかが分かりません。
- 候補の読み直しは 1.5 秒ごと、失敗しても作っている物があれば続けます（app.js:352-367）。回線が切れている間、1.5 秒ごとに失敗のトーストを出し続け、間を空ける仕組みもありません。`online`/`offline` も見ていません。
- 「頼む」は、送っている間に押せなくなりません（app.js:325-348, 719）。2回押すと依頼が2組になり、API のつなぎ先では費用が2倍になります。`aria-disabled` は CSS でマウスだけを止めていて（app.css:74）、キーボードの Enter では押せます。
- `refreshPanel` は、絵を読み終わったときに、まだ同じコマを見ているかを確かめません（app.js:128-151。`loadCandidates` は確かめている）。大きい絵の読み込み（実測 1.5 秒）の間にコマを替えると、前のコマの絵が今のコマに出る可能性があります。そこで囲んで頼むと、違う絵の上の囲みを送ります。未検証ですが、作りから起こり得ます。

### 2.15 進み具合と止める
- **分類：磨けていない／重さ：重要**
- 「n / m 枚」と状態の文字だけです（app.js:438-450）。ステップの進み・残りの時間・順番待ちの何番目かがありません。
- 止めるは組ごとにあります。中の依頼を1件ずつ順に送るので（app.js:452-457）、6件なら6回の往復を待ちます。止まった依頼の「送り直す」「続ける」がありません。
- 1.5 秒ごとに候補の欄を全部作り直します（app.js:377-436）。そのたびに、人の手の範囲を持つ候補ごとに全画素の橙の絵を作り直します（app.js:402-404。1回 726 ms）。600dpi で 4 枚の候補なら、1.5 秒ごとに約 3 秒の処理で画面が固まります。256px の小さい絵に重ねるためだけに全画素で作っています。作り直すたびにフォーカスも消えるので、キーボードで候補を選べません。

### 2.16 アクセシビリティ（作業の流れに関わる所だけ）
- **分類：磨けていない／重さ：後で**
- 道具・切り替えのボタンに `aria-pressed`・`aria-label` が付いており、基本はできています。
- 絵の欄はキーボードで触れません（canvas に `tabindex` が無い）。矢印キーで動かす・拡大する手段が無く、キーだけで作業する人は絵の位置を変えられません。

### 2.17 言語の切り替え
- **分類：足りない／重さ：重要**
- 文言はすべて index.html と app.js に日本語で直接書いてあります。今のアプリは i18next で 8 言語に対応しています。V3 で i18next の仕組みを使わずに書き進めると、後で全部の文言を抜き出す作業になります。日付も `ja-JP` に固定です（app.js:390, 549）。

### 2.18 画面の幅への対応
- **分類：磨けていない／重さ：重要**
- 固定の幅はほぼありません（`minmax(320px,34%)` など最小だけ。app.css:37）。良い作りです。
- 900px 以下では絵の欄の高さが 320px になります（app.css:38。実測：幅 768・高さ 844 で 320px）。ペンで描く主な機器（タブレットの縦向き）で、絵が画面の 4 割弱しか使えません。
- 幅 390px では上の道具の帯が横にはみ出し、ペン・消しゴム・取り消すが見えません。囲む道具の帯が絵の上をほぼ覆います（`audit/narrow_390.png`）。
- 「版を見ています」の帯は `top:112px` で固定です（app.css:125）。道具の帯が折り返すと重なります。

### 2.19 比べる
- **分類：高度化が要る／重さ：重要**
- 比べる画面は全体を縮めた絵だけです（app.js:580-599）。拡大して細部（手・目・線）を、同じ位置で2枚並べて見ることができません。候補を大きい絵の欄に出す手段も、比べる以外にありません。600dpi の候補を選ぶとき、肝心の細部を見られません。

## 4. しっかりしている所

- 囲んだ範囲を絵と同じ大きさの画素で持ち、見えている物と送る物を同じにしている（stage.js:3-4）。人の手の範囲を塗るたびに引く作りも筋が通っています。
- 処理の一覧と入力欄をサーバーの JSON Schema から作る（schema_form.js）。処理を足しても画面を変えずに済みます。
- 採用・却下・版を戻す・ペン・消しゴムを、サーバーの出来事の取り消しで戻す。ペンは「層を作る・線を足す・控えを上げる」を1回の取り消しにまとめています（app.js:637-660）。
- 候補の読み直しで、コマを替えた後の古い結果を捨てる確かめがあります（app.js:354-357）。
- 線の正本を mm の点で持ち、控えの絵に線の版（`stroke_revision`）を付けて上げる作り。
- 道具のボタンに `aria-pressed`・`aria-label`、キーの表示（`kbd`）があり、固定の幅はほぼありません。

## 5. 優先の順（必須だけ）

1. ポインタの出来事を入れ、筆圧が無いときは 0.5 を作らずに「筆圧なし」として持つ（2.1）。
2. 囲む筆の1回の移動で全画素を触らない（`hasMask` を外す・変わった範囲だけ描く）。1つ戻すを差分にする（2.2・2.3）。
3. ペン・消しゴムの往復をやめる。線は画面で先に確定して見せ、保存は後ろで行う。作品全体の読み直しを、変わった物だけの取得にする（2.2・2.3）。
4. 取り消しを1つにまとめ、囲みも Ctrl+Z で戻す。コマを替えたら積み上げを分ける。囲みを消しゴムで失わない（2.6）。
