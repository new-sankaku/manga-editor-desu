## 3. 正本と操作の窓口

- 正本を変えるのは `POST /works/{id}/ops` と取り消し（`POST /works/{id}/events/{event_id}/undo`）だけ。どちらも操作の窓口を通る。
- 1回の操作の流れ
  1. 作品の行を `FOR UPDATE` で取る。作品ごとに書き込みは1本になる（`V3ハーネス設計.md` 9.3）
  2. 権限を確かめる。AIは頼んだ人の権限で確かめる
  3. ロックを確かめる
  4. 正本を変え、出来事を1件追記する。出来事には取り消すときに流す操作も入れる。AIの変更が人の手の印に当たって判断待ちに置いた項目も出来事（`held_changes`）に残し、返事で返す（3.2）
  5. 権限の組（OpenFGA）を書いてから確定する。確定に失敗したら書いた組を戻す
- 操作を足すときは `operations/` に操作の型を1つ書き、`operations/all_operation_types.py` の `Op` の一覧に加えるだけ。窓口（`operations/operation_submit_and_undo.py`）と取り消しは触らない。

| 操作 | 要る権限 | 取り消し |
|---|---|---|
| 作品の設定（題・読む向き・文字の向き・媒体・判型・ページ数） | 作者 | 元の値に戻す |
| 人を招く・外す | 作者 | 逆にする |
| 送ってよい先（APIのつなぎ先）を足す・外す | 作者 | 逆にする |
| 閾値を置く・変える・外す | 作者 | 元の値に戻す |
| 指摘への反応（直した・見送った・指摘が違う） | 見られる人 | できない（記録なので、違えば足し直す） |
| 巻・話・ページを足す | 作者 | 抜く |
| 話を変える（題・番号・締切） | 作者 | 元の値に戻す |
| ページをアシスタントに割り当てる・外す | 作者 | 逆にする |
| コマを足す | そのページを描ける人 | 抜く |
| コマを変える（読む順・枠・役割・中身・使う絵・人の確定印・人の手の印） | そのページを描ける人 | 元の値に戻す |
| ページの段の割りを変える | そのページを描ける人 | 元の値に戻す |
| 巻・話・ページ・コマを抜く・戻す | 作者（コマはそのページを描ける人） | 逆にする |
| ネームの案を出す | 見られる人 | 案を「使わない」にする |
| ネームの案を「使わない」・未決に戻す | 見られる人 | 元の状態に戻す |
| ネームの案を採用する | 作者 | 採用する前のページとコマに戻し、作ったページとコマを抜く |
| 絵を登録する | ページの絵はそのページを描ける人、ページに属さない絵は作者 | できない（絵は消さない） |
| コマを分ける・合わせる・ばらばらに割る・図形のコマ・コマの型を当てる | そのページを描ける人 | 1回で前の行に戻す（`restore_rows`） |
| コマの型を残す | そのページを描ける人 | 抜く |
| トーン・図形を置く・変える・動かさない・仕上げをまとめて戻す | そのページを描ける人（動かさないは人だけ） | 元の値に戻す |
| ペンの線を足す・変える・抜く・線の消しゴム・画素の消しゴム・線の控えの絵 | そのページを描ける人。人だけ | 1回で前の行に戻す |
| 赤入れを付ける・直す・依頼を残す | 赤入れを付けられる人（can_comment） | 元の値に戻す |
| 企画・設定資料を変える・設定資料の案を採る | 作者 | 元の値に戻す |
| 置き換え | 1ページならそのページを描ける人、いくつものページなら作者 | 1回で前の行に戻す |
| 直した PSD を戻す | そのページを描ける人。人だけ | 1回で前の行に戻し、作った判断待ちは取り下げ |
| ページを並べ替える（`reorder_pages`） | 作者。人だけ | 前の番号に戻す |
| 見開きにする（`add_spread`）・解く・戻す（`set_removed` の `spread`） | 作者。人だけ | 逆にする |
| 見開きの絵を置く・替える（`update_spread`） | 前のページを描ける人。人だけ | 元の値に戻す |
| ページの種類・色の種類・解像度・ノンブルの出し方（`update_page`） | そのページを描ける人。人だけ | 元の値に戻す |

- どの操作でも、AIの変更が人の手の印の付いた項目に当たると、断らずにその項目を判断待ちに置き、印の無い項目は当てる（3.2）。どの操作が `V3細部の決めごと.md` 10.1・10.4 のどの行を受けるかは `V3人とAIの受け渡し.md` 6章。
- 消さずに「抜いた」印を付けるので、取り消しの取り消しでやり直しになる。同じ出来事は2回取り消せない。
- 作品を作ったときの出来事（`create_work`）と、ロックの出来事（`lock_acquired`・`lock_released`・`lock_preempted`）も出来事の列に入る。どれも取り消せない。
- ネームの形（ページ・段・コマ・写す範囲・角度・人物・吹き出し・擬音）は `name_structure/name_draft_schema.py` に置いた（試作 p27 の出力の形）。ページとコマの行と、この形の間は `operations/name_draft_conversion.py` で変換する。検査とコマ割りの計算は、この形だけを見て、誰が作ったかは見ない。

### 3.1 ネームの案

- 作り手は3つ：AIが作った（`ai`）・人が別に作った（`human`）・外のネームを取り込んだ（`imported`）。どれも同じ形で、採用すると同じページとコマの行に入る。
- 作り手は偽れない。AIの操作はAIの案だけ、人の操作は人の案か取り込みの案だけを出せる。
- 案そのものは採用しても消さずに残す。採用した案の状態は、採用を取り消すまで変えられない。
- 見る口：`GET /works/{id}/episodes/{episode_id}/name-proposals`（案の一覧）、`.../name-draft`（今のページとコマをネームの形にして返す）。

### 3.2 人の手の印（`V3細部の決めごと.md` 10.2）

- ページとコマを変える操作は、必ず `operations/human_hand_guard.py` を通す。
- 人が変えた項目には、項目ごとに人の手の印を付ける。
- AIは、人の手の印の付いた項目と、人の確定印の付いたコマを書かない。AIの変更が当たると、断らずにその項目を判断待ちに置き、印の無い項目はそのまま当てる。印・確定印のある行をAIが抜く・戻すときも判断待ちに置く。どの操作も `human_hand_guard.py` の1か所を通るので、操作ごとの違いは無い（2026-10-08 に揃えた。前は前からある操作だけ 409 で断っていた）。
- 判断待ちに置いた項目（判断待ちの id・表・行・項目）は、出来事の `held_changes` に残り（移行 0007）、`POST /works/{id}/ops`・取り消しの口の返事の `held_changes` と、`GET /works/{id}/events` で見える。AIの操作を流す側（順番待ちの作業者など）は、返った出来事の `held_changes` で分かる。
- 人は `GET /works/{id}/held-changes` で見て、`resolve_held_change` で採る（accept）・採らない（reject）・戻す（reopen）を選ぶ。判断待ちを置いた操作を取り消すと、まだ決めていない判断待ちは withdrawn になり、やり直すと開き直す（窓口が取り消しの操作を `undo_with_held_changes` で包む）。
- 人の手の印を外せるのは人だけ（`human_hand_fields` を明示して渡す）。
- 人が案を採用したときは上書きする。人の案・取り込みの案なら書いた項目に印を付け、AIの案なら印を外す。
- AIが案を採用したとき・人がAIの案を採用したときは、人の手の所と確定印のコマは書かず、判断待ちに置いて出来事に残す。

### 3.3 絵のファイル

- 生成した絵・人が描いた絵・外から持ち込んだ絵を、同じ表（`image_files`）と同じ操作（絵を登録する）で持つ。違うのは出どころの印だけ。
- 出どころは偽れない。AIが登録できるのは生成した絵だけ（依頼の ID が要る）。人は描いた絵と持ち込んだ絵（持ち込みは元を書く）。
- ファイルの中身は置き場に、中身の sha256 を名前にして置く。同じ絵は1つだけ置かれる。今の置き場はサーバーの手元のフォルダ（`.env` の `V3_IMAGE_DIR`）だけ。無ければ絵を扱う口は止まる。
- 受け付ける形式は PNG・JPEG・WEBP・TIFF。
- 口：`POST /works/{id}/images`（人が描いた絵・持ち込んだ絵を受け取る）、`GET /works/{id}/images`、`GET /works/{id}/images/{image_id}/file`。生成した絵は、順番待ちの作業者が頼んだ人の権限で同じ操作を使って登録する（7章）。
- コマに使う絵を選ぶのはコマを変える操作の `image_id`。人が選ぶと人の手の印が付き、AIが替えようとすると判断待ちになる。
- 画像生成（文から絵・絵から作り直す・似た別案・囲んで直す・描き足す・指示で直す）は、処理の一覧（`generation_queue/image_process_registry.py`）から引数・入力欄・ComfyUI の手順を作る。できた絵は候補として登録され、採用・取り消し・却下・比べる・版を見るができる。口・下ごしらえ・画面は `V3画像生成の機能と画面.md`。

### 3.4 ネームの検査

- `POST /works/{id}/episodes/{episode_id}/name-checks` で回す。`proposal_id` を渡すと採用する前の案を、渡さなければ今のページとコマを検査する。どちらも同じ検査にかかる。
- 閾値は作品の閾値の表から、検査の鍵の行だけを読む。値の形は `{"value": 数}`。検証の状態が `rejected` の行は使わない。`unverified` の行は使い、結果に状態を添える（`V3ハーネス設計.md` 7章）。
- 閾値の無い検査は値だけを返し、合否を出さない（「閾値未設定」）。枠・人物の位置・吹き出しの位置が無いと計算できない検査は「データなし」。
- 結果は回すたびに1行足す（`name_check_runs`。使った閾値も残す）。作品データではないので操作の窓口を通さない。`GET` で一覧を見る。鍵と意味の一覧は `GET /name-checks/threshold-keys`。

### 3.5 原稿として出す形（`V3点検の結果.md` §3）

- **設定**（`name_structure/print_settings.py`。どれも既定の値を置かず、無ければ書き出しを止める）
  - 作品の `preferences.print`：作品の略号（ファイル名の頭）・色の種類の既定・色の種類ごとの解像度・2階調の決まり（線と文字の閾値、絵の網点の線数・角度・形、PDF の2値の符号化）・安全線（上・下・ノド・小口）・ページ数の倍数（4・8・無し）と数える範囲（話・巻）
  - 作品の `preferences.nombre`：書体・大きさ・隠しノンブルの大きさ・色・始まりの番号・数える範囲・見せる位置（上か下、小口か真ん中、端からの mm）・隠す位置（ノドの近く）・ページの種類ごとの出し方（見せる・隠す・出さない）
  - 作品の `preferences.typesetting` と文字の `typesetting`：行間（文字の大きさとの比）・自動の改行（しない・字の間・文節）・縦中横の桁数の上限・「!?」を縦中横にするか・揃え
  - ページの行：`page_kind`（表紙・カラー・本文・白ページ）・`color_mode`・`dpi`・`nombre_display`（作品の既定を上書き）
  - 文字の `spans`：何文字目から何文字目までの書体・大きさの比・太らせる幅・色。範囲は重ねない
- **並びと見開き**（`print_export/book_layout.py` の1か所。並べ替えの操作・書き出し・入稿前の確かめが同じここを使う）
  - ページの左右は話ごとに、作品の `first_page_is_left` から交互に決める
  - 見開きは話の中で隣り合う2ページ。右から読む本は前のページが右、左から読む本は前が左（絵は反転しない）。組が崩れる並べ替え・見開きの追加・戻しは止める。ページを足す・抜くで崩れたときは、書き出しと入稿前の確かめが止める
  - 見開きの絵の座標は、左のページの基本枠の左上を原点にした mm（`spreads` の表）
- **書き出し**（`print_export/export_runner.py`）
  - 解像度はページごと（`dpi` を渡すと全ページをその値にする）。色の種類の絵は `print_export/color_mode_output.py`：2階調は層ごとに白黒にしてから重ねる（線・ベタ・文字・人の手・枠・フキダシ・トーンは閾値、コマの絵と見開きの絵と絵の層は網点。網の目はページの画素で揃える）。PNG は 1ビット・8ビットの灰色・RGB で保存する。PSD は色の種類によらず RGB の層
  - 見開きは `spread_output` で選ぶ：`joined`（1枚）・`split`（ノドで2ページ。どちらも塗り足しの幅だけ相手のページの絵を含む）・`both`。各ページの層はノドで切り、ノドをまたぐのは見開きの絵だけ。PDF は `split` だけ、PSD は `joined` だけ。見開きの PSD は戻せない
  - ファイル名は `略号_話2桁_ページ3桁`（ページは話の中の位置）、見開き1枚は `略号_話_前-後`、PDF は `略号.pdf`。出力の記録に `dpi`・`color_mode`（見開きは `spread_id`）を持つ。直した PSD の戻しは出力の `dpi` で座標を戻す
  - ノンブルは `preferences.nombre` があるときに描く（層の名前「ノンブル」）
  - フキダシのしっぽ：外形の中の点から文字の `tail_target_mm` へ引いた線が外形を出る所を根元にし、根元の幅（`tail_base_width_mm`）と曲がり（`tail_bend_ratio`、2次の曲線）で形を作り、外形と1つの形にして（shapely）線を引く。`joined_to_previous` のフキダシも同じコマの前のフキダシと1つの形にする
  - グラデトーンは、濃さを `density` から `density_end` へ変えた灰色を網点（`lines_per_inch`・`screen_angle_deg`・`dot_shape`）にする
- **縦組み**（`v3/psd_writer/text_layout.js`。描くのは `render_text.js`）

## 4. ロック

- ページ・コマ・個別の3段（`V3ハーネス設計.md` 4.3）。期限は `.env` の `V3_LOCK_TTL_SECONDS`（既定900秒）。
- コマ・個別を取るときは、同じ物と、それが入っているページのロックにぶつかる。同じページの別のコマのロックにはぶつからない。
- ページを取るとき、ページを抜くときは、そのページの中のコマ・個別のロックにもぶつかる。
- 人は、AIのロックを取得の操作で取り返せる。取り返したロックの依頼は取り消す。人どうし・AIどうしでは取り返さない。
- 外せるのは持ち主だけ。

## 6. 送り先の制限

## 7. 順番待ち

- 1件の依頼は Temporal の流れ1つ。流れは制御の待ち行列（`v3-control`）で動き、送信はつなぎ先ごとの待ち行列（`v3-service-{id}`）で動く。
- 「1件ずつ」は作業者の同時実行数を1に、「同時にN件まで」はNにする（`V3細部の決めごと.md` 4.2）。
- 休ませたつなぎ先は作業者を止める。頼んだものは待ち行列に残り、戻すと順に送る。作業者はつなぎ先の表を3秒ごとに読み直す。
- 人が画面で頼んだものを、AIが工程を進めるための依頼より先に送る（同 4.4）。Temporal の優先順位（`priority_key`、人1・AI3）を使う。
- 優先順位が同じ依頼の中では、作品ごとに順に回す（`V3ハーネス設計.md` 2.4の29）。Temporal の公平さの鍵（`fairness_key`）に作品の ID を入れる。サーバー側で `matching.enableFairness` を入れていないと鍵は無視されるので、compose で入れてある（試作 p57）。
- 送る前に、作品の送ってよい先と、つなぎ先の月の予算（呼び出しの記録の費用の合計）を確かめる。
- 頼んだ順を守るため、依頼を受ける口（`POST /works/{id}/jobs` など。中は `job_start_and_control.enqueue`）は、送信がつなぎ先の待ち行列に入ってから返す。流れを始めるのと、流れの更新 `until_queued`（送信を待ち行列に入れたら返る）を1回で頼む（Temporal の update-with-start）。始めただけで返すと、続けて頼んだ依頼が待ち行列に入る順が頼んだ順と入れ替わった（下の8章）。
- `QUEUE_ENTRY_WAIT`（30秒、`queue_names_and_priority.py`）待っても待ち行列に入らなければ（制御の作業者が動いていない）、流れを終わらせ、依頼を `stopped`（失敗の種類 `queue_not_running`）にし、口は 503 を返す。

失敗したとき（`V3細部の決めごと.md` 4.5）

| 失敗 | 依頼の状態 | 扱い |
|---|---|---|
| 回数・同時実行の制限 | `waiting_limit` | 提供元が返した時間（無ければ30秒）待って、同じ先へ送り直す。送り直しの回数に数えない |
| 時間切れ・通信の失敗 | `running` のまま送り直し、超えたら `stopped` | 処理ごとの `resend_limit` 回まで送り直す |
| 内容で断られた | `stopped` | 送り直さない |
| 返ってきた形が崩れている | `stopped` | 使わない |
| 予算の上限 | `waiting_budget` | 人が上限を上げて「続ける」（`/resume`）を押すまで待つ |
| 送ってよい先から外された | `stopped` | 送らない |
| 待ち行列に入れられなかった（制御の作業者が動いていない） | `stopped`（`queue_not_running`） | 口は 503 を返す。「もう一度」で頼み直せる |

- 止まったものは「もう一度」（`/retry`）で、いまの処理ごとの送り先へ同じ中身で頼み直す。
- 取り消す（`/cancel`）と、送っている途中でも止めて `cancelled` にする。
- 呼び出しの記録には、送った・送らなかったの両方を残す（呼び先・モデル・設定・seed・トークン数・費用・時間・失敗の種類）。費用はつなぎ先と処理の組ごとに人が入れた1回の単価。

ComfyUI への送信（`service_senders/comfyui_sender.py`。試作 p56 で本物の ComfyUI 0.39.2 に送って確かめた形）

- 処理ごとの送り先に手順（API 形式）を持たせ、依頼の `overrides`（ノード番号 → 入力名 → 値）で値を差し替えて `/prompt` に送る。`/history` で終わりを待ち、`/view` で絵を受け取る。
- 受け取った絵は置き場に置き、依頼の `register`（絵の役目は必須、ページ・コマは省ける）で登録する。登録の役目が無い依頼は送らずに止める。登録を断られたら依頼は止まる。
- 処理ごとの送り先に、待ちの上限（秒、`comfy_wait_seconds`）と、送る前に選べる値を ComfyUI の一覧で確かめるかの切り替え（`comfy_check_choices`）を持つ。

| ComfyUI の返事 | 失敗の種類 |
|---|---|
| `/prompt` の 429 | 回数・同時実行の制限（`Retry-After` を使う） |
| `/prompt` の 5xx | 通信の失敗 |
| `/prompt` のほかの 4xx（手順を確かめて断った） | 内容で断られた。`error.type` と `node_errors` の要点を詳細の先頭に出す |
| `/history` の 429・5xx | 制限・通信の失敗 |
| `/history` のほかの 4xx、辞書でない本体 | 返ってきた形が崩れている |
| 実行時の失敗 | 内容で断られた（詳細は `exception_message`） |
| 外から止められた | 止められた（`interrupted`） |
| 待ちにも実行中にも履歴にも無い、待ちの上限を超えた | 通信の失敗 |

- 取り消すと、待ちの物は `/queue` から消し、自分の依頼が実行中なら `/interrupt` で止める。

検出器への送信（`service_senders/detector_sender.py`）

- 依頼の `endpoint` で検出器の口を選び、`images` に絵の sha256 を入れる。絵は置き場から読んで送る。閾値などは `form` で渡す（省いた項目は検出器の側で imgutils の既定に任せる）。
