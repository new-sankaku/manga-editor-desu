# V3サーバーの土台

作成 2026-10-07。`次期サーバー化計画.md` を進めると決めた（利用者の指示 2026-10-07「サーバー化計画をやりましょう」）。
その最初として、`V3ハーネス設計.md` 16章の1番（正本・操作の窓口・ロック・取り消し・権限・送り先の制限・順番待ち・呼び出し口の記録・閾値の持ち方・指摘への人の反応の記録）を `v3/server/` に作った。

- 今のアプリ（`file://` で動くもの）には手を入れていない。V3は別のアプリとしてサーバーで動く。
- 言語はPython（`V3ハーネス設計.md` 17章の3）。既製品は同 3.1 の候補から選んだ。

## 1. 動かし方

```
cd v3/server
cp .env.example .env            # LITELLM_MASTER_KEY に任意の長い文字列を入れる
docker compose up -d            # PostgreSQL・Temporal・OpenFGA・LiteLLM
uv sync
uv run alembic upgrade head     # 表を作る
uv run python -m v3server.cli grant-admin <利用者>   # つなぎ先を登録できる人
uv run uvicorn v3server.api.app:app --port 8000      # 画面から呼ぶ口
uv run python -m v3server.queue.worker               # 順番待ちの作業者
uv run pytest                   # 試験（compose が動いていること）
```

| 既製品 | 手元の口 | 役目 |
|---|---|---|
| PostgreSQL 16 | 55432 | 正本。データベース `v3`（本番）、`v3_test`（試験）、`openfga` |
| Temporal 1.9.1（Server 1.32.0）開発用 | 57233、画面 58233 | 順番待ちと送り直し |
| OpenFGA v1.22.0 | 58080 | 権限 |
| LiteLLM v1.104.1 | 54000 | 呼び出し口のうちLLM・VLM |

- ログインはまだ無い。`.env` の `V3_DEV_AUTH=1` のときだけ、見出し `X-V3-User` の値を利用者として受け取る。それ以外ではすべて401。
- LLMのつなぎ先は `docker/litellm.yaml` の `model_list` に足し、そのモデル名を処理の中身（`PUT /services/{id}/processes/{処理}` の `model`）に入れる。APIキーは LiteLLM だけが持つ（`V3ハーネス設計.md` 11章の鍵）。別のモデルへの自動の切り替えは同じファイルで切ってある（方針7）。

## 3. 正本と操作の窓口

- 正本を変えるのは `POST /works/{id}/ops` と取り消し（`POST /works/{id}/events/{event_id}/undo`）だけ。どちらも操作の窓口を通る。
- 1回の操作の流れ
  1. 作品の行を `FOR UPDATE` で取る。作品ごとに書き込みは1本になる（`V3ハーネス設計.md` 9.3）
  2. 権限を確かめる。AIは頼んだ人の権限で確かめる
  3. ロックを確かめる
  4. 正本を変え、出来事を1件追記する。出来事には取り消すときに流す操作も入れる
  5. 権限の組（OpenFGA）を書いてから確定する。確定に失敗したら書いた組を戻す
- 操作を足すときは `ops/catalog.py` に1つ書き、`Op` の一覧に加えるだけ。窓口と取り消しは触らない。

| 操作 | 要る権限 | 取り消し |
|---|---|---|
| 作品の設定（題・読む向き・文字の向き・媒体・判型・ページ数） | 作者 | 元の値に戻す |
| 人を招く・外す | 作者 | 逆にする |
| 送ってよい先（APIのつなぎ先）を足す・外す | 作者 | 逆にする |
| 閾値を置く・変える・外す | 作者 | 元の値に戻す |
| 指摘への反応（直した・見送った・指摘が違う） | 見られる人 | できない（記録なので、違えば足し直す） |
| 巻・話・ページを足す | 作者 | 抜く |
| 話を変える（題・番号・締切） | 作者 | 元の値に戻す |
| ページをアシスタントに割り当てる・外す | 作者 | 逆にする |
| コマを足す | そのページを描ける人 | 抜く |
| コマを変える（読む順・枠・役割・中身・人の確定印） | そのページを描ける人 | 元の値に戻す |
| 巻・話・ページ・コマを抜く・戻す | 作者（コマはそのページを描ける人） | 逆にする |

- 消さずに「抜いた」印を付けるので、取り消しの取り消しでやり直しになる。同じ出来事は2回取り消せない。
- 作品を作ったときの出来事（`create_work`）と、ロックの出来事（`lock_acquired`・`lock_released`・`lock_preempted`）も出来事の列に入る。どれも取り消せない。
- コマの「中身」の形（場所・登場人物・セリフなど、`V3ハーネス設計.md` 4.2）はまだ決めていない。今は自由な形のまま持つ。工程を作るときに決める。

## 4. ロック

- ページ・コマ・個別の3段（`V3ハーネス設計.md` 4.3）。期限は `.env` の `V3_LOCK_TTL_SECONDS`（既定900秒）。
- コマ・個別を取るときは、同じ物と、それが入っているページのロックにぶつかる。同じページの別のコマのロックにはぶつからない。
- ページを取るとき、ページを抜くときは、そのページの中のコマ・個別のロックにもぶつかる。
- 人は、AIのロックを取得の操作で取り返せる。取り返したロックの依頼は取り消す。人どうし・AIどうしでは取り返さない。
- 外せるのは持ち主だけ。

## 5. 権限

OpenFGA に置く。モデルは `openfga/model.fga`。変えたら次で `model.json` を作り直す（サーバーは起動時に変わったことを見て新しいモデルを書く）。

```
docker run --rm -v "$PWD/openfga:/m" openfga/cli model transform --file /m/model.fga > openfga/model.json
```

| 役 | 見る | 描く | 作品の管理 |
|---|---|---|---|
| 作者（author） | ○ | 全ページ | ○ |
| 編集者（editor） | ○ | — | — |
| アシスタント（assistant） | ○ | 割り当てたページだけ | — |
| 原作者・依頼主（client） | ○ | — | — |
| 翻訳者（translator） | ○ | — | — |
| 見るだけ（viewer） | ○ | — | — |

- 赤入れ・承認・翻訳の権限（`can_comment`・`can_approve`・`can_translate`）はモデルに置いたが、それを使う操作はまだ無い。
- つなぎ先と処理ごとの送り先は全作品で共通なので、サーバーの管理者（`system:main` の `admin`）だけが変えられる。最初の管理者は `v3server.cli grant-admin` で付ける。

## 6. 送り先の制限

- 手元（`location=local`）は外へ出ないので、どの作品からも送ってよい。
- API（`location=api`）は、作品の送ってよい先に載っているものだけ。新しい作品では空なので、既定は「手元だけ」（`V3ハーネス設計.md` 17章の6）。
- 確かめるのは2回。頼んだとき（送れない先なら403）と、送る直前（待っている間に外されたら送らず、止まった印を付ける）。
- 別の先へは自動で回さない（方針7）。

---

## 7. 順番待ち

- 1件の依頼は Temporal の流れ1つ。流れは制御の待ち行列（`v3-control`）で動き、送信はつなぎ先ごとの待ち行列（`v3-service-{id}`）で動く。
- 「1件ずつ」は作業者の同時実行数を1に、「同時にN件まで」はNにする（`V3細部の決めごと.md` 4.2）。
- 休ませたつなぎ先は作業者を止める。頼んだものは待ち行列に残り、戻すと順に送る。作業者はつなぎ先の表を3秒ごとに読み直す。
- 人が画面で頼んだものを、AIが工程を進めるための依頼より先に送る（同 4.4）。Temporal の優先順位（`priority_key`、人1・AI3）を使う。
- 送る前に、作品の送ってよい先と、つなぎ先の月の予算（呼び出しの記録の費用の合計）を確かめる。

失敗したとき（`V3細部の決めごと.md` 4.5）

| 失敗 | 依頼の状態 | 扱い |
|---|---|---|
| 回数・同時実行の制限 | `waiting_limit` | 提供元が返した時間（無ければ30秒）待って、同じ先へ送り直す。送り直しの回数に数えない |
| 時間切れ・通信の失敗 | `running` のまま送り直し、超えたら `stopped` | 処理ごとの `resend_limit` 回まで送り直す |
| 内容で断られた | `stopped` | 送り直さない |
| 返ってきた形が崩れている | `stopped` | 使わない |
| 予算の上限 | `waiting_budget` | 人が上限を上げて「続ける」（`/resume`）を押すまで待つ |
| 送ってよい先から外された | `stopped` | 送らない |

- 止まったものは「もう一度」（`/retry`）で、いまの処理ごとの送り先へ同じ中身で頼み直す。
- 取り消す（`/cancel`）と、送っている途中でも止めて `cancelled` にする。
- 呼び出しの記録には、送った・送らなかったの両方を残す（呼び先・モデル・設定・seed・トークン数・費用・時間・失敗の種類）。費用はつなぎ先と処理の組ごとに人が入れた1回の単価。

## 8. 確かめたこと（2026-10-07）

試験19件がすべて通る（`uv run pytest`、2回）。compose の既製品を実際に使い、つなぎ先への送信だけを差し替えている。

| 確かめたこと | 結果 |
|---|---|
| 出来事が作品ごとに1から順に積まれる。20件を同時に送っても番号が飛ばず重ならない | ○ |
| 取り消し・取り消しの取り消し・2回目の取り消しの拒否・追加の取り消しで抜く | ○ |
| 見るだけ・編集者は描けない。アシスタントは割り当てたページだけ描ける。招かれていない人は見られない | ○ |
| 人のロックは他の人を止める。コマのロック中はページも取れない。ページを抜く操作はページの中のロックで止まる | ○ |
| 人はAIのロックを取り返せる。AIは人のロックを取れない | ○ |
| 「1件ずつ」で同時実行が1、「同時に3件まで」で3 | ○ |
| APIの先は送ってよい先に無ければ頼めない。待っている間に外されたら送らない | ○ |
| 休ませた先の依頼は待ちに残り、戻すと送られる | ○ |
| 断られたら1回で止まる。通信の失敗は2回送り直して3回目で通る。超えたら止まる。制限は回数に数えず送り直す | ○ |
| 送っている途中に取り消すと止まる | ○ |
| 予算の上限で待ち、上限を上げて続けると送られる | ○ |
| 人の依頼がAIの依頼より先に送られる | ○（下の条件つき） |
| LiteLLM 経由の呼び出し。試験用の返答を返すモデル（`mock_response`）で、文字・トークン数を受け取れる | ○ |

- 人の依頼を先にする優先順位は、Temporal の待ち行列の分割が4つ（既定）だと守られなかった（3回中2回で、AIの依頼が人の依頼の間に入った）。分割を1つにすると3回とも守られた。compose で分割を1つにしてある。
- LiteLLM に無いモデル名を送ると400が返り、「内容で断られた」として止まる。設定の誤りも同じ扱いになる。
