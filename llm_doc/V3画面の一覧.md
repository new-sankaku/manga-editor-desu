# V3 の画面の一覧（作品をまたぐ画面）

作品と話・企画・構成・設定資料・書き出し・生成サービス・取り込み・翻訳・確認の 9 画面と、画面どうしをつなぐ帯・カラーテーマをまとめる。
画像生成の画面は `V3画像生成の機能と画面.md`、原稿の画面と工程（ハーネス）の画面は、それぞれを作っている所の文書を見る。

## 1. 動かし方

- サーバー（`v3/server`）が `/web/` で画面を出す。動かし方は `V3サーバーの土台.md`。開くのは `http://<サーバー>/web/<画面>/`（例 `/web/works/`）。
- 利用者は右上の「利用者（開発用）」の欄（localStorage の `v3.user`。画像生成の画面と同じ）。名乗り方は起動時に `GET /auth/mode` で読む（`js/api.js` の `loadAuth`）。今はローカル（`dev_header`）で、サーバーへはヘッダー `X-V3-User` で送る。API を呼ぶのは `js/api.js` の `authFetch` の1か所で、書き換えの API には `X-V3-Request: 1` も付ける（`V3サーバーの土台.md` 1.3）。
- 選んだ作品は `?work=` と localStorage の `v3.work`、話は `?episode=` と `v3.episode` に残す。帯のリンクは `?work=` を付けて渡す。
- 部品は lit-html（`v3/web/vendor/lit-html-3.2.1`）と lucide。画面ごとに状態を持ち、変わったら `draw()` で全体を描き直す。正本を変えるのは操作の窓口（`POST /works/{id}/ops`）だけ。

### 2.1 キー・集中モード・全画面を入れるとき（2026-10-08。全部の画面に入れた）
画面に入れる手順（作品をまたぐ画面は `shell.js` の `startShell` が `startKeys` を呼ぶので、下の 2 と 3 だけ）：
1. `api.loadAuth()` のあとで `startKeys("<画面の名前>")` を呼ぶ（`common/keys.js`。利用者の割り当てを読むので、名乗り方が決まってから）。画面のキーは、その前か後で `km.bind("<操作の名前>", 処理)` で結ぶ。新しい操作は `key_catalog.js` に足す（画面の中でキーを受ける処理を書かない）。
2. `<link rel="stylesheet" href="…/common/keys.css">` を足す。lucide を読んでいない画面は `vendor/lucide-0.468.0/lucide.min.js` も読む（キーの一覧の印に使う）。
3. 集中モードのときに隠す物に `data-v3-panel` を付ける。集中モードのときの並べ直しは、その画面の CSS に `html[data-focus]:not([data-peek]) …` で書く。
4. ボタンに `data-key="<操作の名前>"` と空の `<kbd></kbd>` を付けると、キーと `title` が入る。
5. 色は `theme.css` の名前だけを使う。canvas の色は `common/theme_colors.js`（原稿は `manuscript/js/theme_colors.js`）で読む。`node v3/web/test/theme_check.mjs` を流す。

- 原稿の画面（入れた）：上の帯・画面の帯・下のページの一覧・右のパネルが `data-v3-panel`。集中モードはページだけ。22.2 のキーはそのまま。R（赤入れ）・B（ペン）・E（消しゴム）・U（図形）・O（読む順）・Q（キュー）は、この画面に機能が無いので「まだ無い」と通知する。1〜6（候補・赤入れの選択肢）・I（指示の欄）・Ctrl+Enter（生成）・Alt（スポイト）は結んでいない（候補・指示の欄・スポイトが無い）。G のあとの画面の切り替えは効く。色は `print_colors.js`（刷る黒と紙の白）だけを、色の検査がファイルごと許す。
- 工程の画面（入れた）：上の帯・画面の帯・右のパネル・ページとコマの表が `data-v3-panel`。集中モードは図だけ（見張る画面）。図の大きさが変わると Cytoscape に `resize()` と `fit()` を送る（`v3-view` を受ける）。キーは 0（図の全体を見る）。状態の色（`--run-bg`・`--retry`・`--stale`・`--stale-tint`・`--hot-glow`・`--hot-glow-2`・`--bad-stripe`）は色のルールに入れた。図の色は今のまま `harness_graph.js` が `getComputedStyle` で読む。
- 画像生成の画面（入れた）：上の帯・画面の帯が `data-v3-panel`。集中モードは、絵と下の候補の帯（右のパネルの「候補」だけを横に並べる。`data-v3-strip`）。
- 確認の画面（入れた）：「読み通す」ボタンで集中モードにし、ページを大きく1枚ずつ出す。矢印は読む向きに合わせる。
画像生成の画面（`v3/web/index.html`）には帯の 3 行だけを足した。画像生成の画面は `?work=` を読まない（作品は自分の欄で選ぶ）。

画面ごとの振る舞い：
- 作品と話：話は巻ごとに並べ、話ごとに確認の状態の帯・数・確認待ちのページ（確認の画面へのリンク）・締切の見込みを出す。見込みの出し方はサーバーの計算のままで、当たるかは未検証。
- 企画：作品の設定（題・媒体・読む向き・文字の向き・判型・ページの寸法・作品の言語）と入稿の設定（印刷・2階調・ノンブル・組版。作品の preferences。`V3サーバーの土台.md` 3.6）を折りたためる組で出す。AIの関与（4択）もここで選ぶ。
- 構成：ページを並べ、確認の状態・ページの種類・色・見開き・締切に遅れる見込みの印を付ける。選んだページを前後へ動かす・次のページと見開きにする・外す・削除・ページの設定・割り当て。
- 設定資料：人物・場所・小物・その他に分けて探せる一覧と、選んだ物の中身（名前・特徴・メモ・絵・服・生成の設定（見た目の指示・入れない指示・seed・LoRA・参照の絵））。AIが足した案は採るか捨てるかを選ぶ。
- 書き出し：ページを選び、ファイル（PNG・PDF・PSD）・見開き（選んだページに見開きがあるときだけ送る）・言語・解像度を決める。先に「確かめる」（preflight）を押し、選び直したら確かめ直すまで書き出せない。止まる問題があっても書き出しは押せる（サーバーが止める）。書き出しの段（順番待ち・書き出している・できた・失敗）を 1.5 秒ごとに読み、できたファイルを保存する。
- 生成サービス：処理ごとの送り先を表で選ぶ（今の送り先の作業と手を引き継いで PUT する）。プリセット（安い・良い・ローカル・API）は、送れる先（接続済み・一時停止中でない）から並びを計算して見せてから当てる。接続先ごとのカードで一時停止・URL・送り方・予算・利用規約の要点を直す。受けられる処理は読むだけ。
- 取り込み：作品のページの寸法（page_spec）が無いと取り込めない（企画へのリンクを出す）。報告は元のページごとに、そのまま入れた・形を変えて入れた・入れられなかった・要らないで絞れる（最初は形を変えた物と入れられなかった物だけ）。
- 翻訳：言語を入れると（`?lang=` と localStorage の `v3.lang`。画面の言語とは別。画面の言語は `?ui=` と `v3.ui_lang`）、ページごとに元の文字と訳文を左右に並べる（狭い幅では上下）。訳文・向き・大きさを直して「残す」。訳の無い文字だけに絞れる。作品の言語が決まっていない・作品の言語を選んだときは訳せない理由を出す。
- 確認：今の状態から移れる先だけをボタンにする（下書き→確認に出す、確認待ち→承認する・修正を依頼・引っ込める、直しが要る→直して出し直す、承認→開け直す）。修正を依頼するにはコメントが要る。記録は新しい順で、最後の記録だけ取り消せる。誰が押せるかはサーバーが決め、断られたら理由を通知に出す。

## 4. 試験とスクリーンショット

まとめて流す（2026-10-08。`v3/web/test/run_ui.mjs`。`v3/run_tests.sh` の fast・full・perf から呼ぶ）

```
NODE_PATH=/opt/node22/lib/node_modules PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node v3/web/test/run_ui.mjs fast
V3_ORIGIN=http://127.0.0.1:<ポート> CTRL=http://127.0.0.1:<見本のポート+1> node v3/web/test/run_ui.mjs full
node v3/web/test/run_ui.mjs perf
```

保存と起こし直しの通し試験は別の組（`v3/run_tests.sh e2e`。`v3/web/test/persistence_e2e.mjs`）。別の compose の組 `v3pe` を立て、原稿の画面と作業台で直してから、開き直し・サーバーとワーカーの再起動・compose の down と up の後に、正本・ピクセル・DOM・確認待ち・書き出し・取り消しを見る。スクリーンショットは `SHOTS=<フォルダ>` のときだけ残す。手順と結果は `V3サーバーの土台.md` 8.1。

- ブラウザは1回だけ起こし（`chromium.launchServer`）、試験のファイルごとに別のプロセスで同時に流す（CPU の数まで）。各ファイルは `PW_WS` で接続し、自分の context を作る（`ui_common.mjs` の `openBrowser`）。`harness_ui` は変化が出るまでの遅れを測るので、ほかが終わってから1本で流す。
- fast：`theme_check`・`i18n_check`（訳し漏れ。ブラウザは要らない）・`keys_ui`（偽のサーバー）・`manuscript_ui`（`MOCK=1`。`manuscript_mock_server.mjs`）・`screens_ui`（`REPLAY=1`。録った答え）。本物のサーバーは要らない。
- full：fast ＋ `manuscript_ui` と `screens_ui` を本物のサーバーで、`harness_ui` を動く見本で。`image_generation_ui` は `IMAGEGEN_WEB`・`IMAGEGEN_USER` があるときだけ（未検証。ComfyUI が要る）。要る変数が無ければ止まる。
- perf：`manuscript_ui` を `PERF=1` で（線を引く動きを 60 回・保存 10 回。普段は 12 回・2 回で、動かす距離は同じ）。
- 録った答え（`v3/web/test/recorded/screens_ui.json`。59 件）：本物のサーバーに向けて `RECORD=1 V3_WEB=<本物>/web/ node v3/web/test/screens_ui.mjs` で録り直す。API の答えの形を変えたら録り直す。返すとき（`recorded_api.mjs`）は「メソッド・パス・利用者」ごとに録った順に答え、録っていない・録った数より多い呼び出しは 500 を返して誤りに数え、JSON の本文が録ったときと違っても誤り、録ったのに呼ばれなかった答えも誤り（ほかの答えで埋めない）。
- 試験だけの設定：`localStorage` の `v3.test.poll_ms`（進行状況を読む間。`common/poll_interval.js`。入っていると画面の左下に「試験の設定：…」と出る）、`SHOTS=<フォルダ>`（写しを撮る。無ければ撮らない）。
- 決め打ちの待ち（`waitForTimeout`・`networkidle`）は、`keys_ui`・`manuscript_ui`・`screens_ui` から無くした（状態を待つ。`settled` は描画を2回待つ）。`harness_ui` と `image_generation_ui` には残っている。
