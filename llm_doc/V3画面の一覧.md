# V3 の画面の一覧（作品をまたぐ画面）

作品と話・企画・構成・設定資料・書き出し・生成サービス・取り込み・翻訳・確認の 9 画面と、画面どうしをつなぐ帯・色の組をまとめる。
画像生成の画面は `V3画像生成の機能と画面.md`、原稿の画面と工程（ハーネス）の画面は、それぞれを作っている所の文書を見る。

## 1. 動かし方

- サーバー（`v3/server`）が `/web/` で画面を出す。動かし方は `V3サーバーの土台.md`。開くのは `http://<サーバー>/web/<画面>/`（例 `/web/works/`）。
- 利用者は右上の「利用者（開発用）」の欄（localStorage の `v3.user`。画像生成の画面と同じ）。名乗り方は起動時に `GET /auth/mode` で読む（`js/api.js` の `loadAuth`）。今はローカル（`dev_header`）で、サーバーへは見出し `X-V3-User` で送る。口を呼ぶのは `js/api.js` の `authFetch` の1か所で、書き換えの口には `X-V3-Request: 1` も付ける（`V3サーバーの土台.md` 1.3）。
- 選んだ作品は `?work=` と localStorage の `v3.work`、話は `?episode=` と `v3.episode` に残す。帯のリンクは `?work=` を付けて渡す。
- 部品は lit-html（`v3/web/vendor/lit-html-3.2.1`）と lucide。画面ごとに状態を持ち、変わったら `draw()` で全体を描き直す。正本を変えるのは操作の窓口（`POST /works/{id}/ops`）だけ。

## 2. 共通の部品（`v3/web/common/`）

| ファイル | 中身 |
|---|---|
| `theme.css` | 色の組（:root）。明るい表示だけ。砂とベージュの色（NieR:Automata のような砂漠の色）。試作 `v3poc/screen/index.html`（worktree-agent-a41e21f1118f09fde）の色に合わせた。ページ・候補の絵など紙の物（`.paper`・`.cand`）は白のまま |
| `nav.js`・`nav.css` | 画面どうしをつなぐ帯。`<nav class="v3-nav" data-v3-nav="<画面の id>">` を置き、`nav.js` を読めば中身を入れる。並び：作品と話・企画・構成・設定資料・工程（harness）・原稿（manuscript）・画像生成・翻訳・確認・書き出し・取り込み・生成サービス |
| `shell.js` | 上の帯（画面の名前・作品を選ぶ欄・利用者）、知らせ（toast）、`send`・`raw`（PUT・PATCH とファイルを取る GET。`js/api.js` に無い分）、言葉の対応（役・確認の状態・ページの種類など）、話を選ぶ欄 |
| `form_fields.js` | 項目の並びから入力欄を作り、読み返す（空は null）。利用規約の要点（UsageTerms）の欄 |
| `common.css` | 画面の置き方（段・カード・表・ページの並び・タブ）。幅は決め打ちにせず、狭いと1段に落とす |

`v3/web/css/app.css`（画像生成の画面）も `theme.css` を読み、色の値だけを組の名前に置き換えた（形は変えていない）。
原稿の画面・工程の画面も、`<link rel="stylesheet" href="../common/theme.css">`（または app.css を読む）と、帯の 3 行（`nav.css`・`<nav class="v3-nav" data-v3-nav="manuscript">`・`nav.js`）を足せば同じ色と帯になる。
画像生成の画面（`v3/web/index.html`）には帯の 3 行だけを足した。画像生成の画面は `?work=` を読まない（作品は自分の欄で選ぶ）。

## 3. 画面ごとの口

| 画面 | 置き場 | 読む口 | 変える口（操作は ops） |
|---|---|---|---|
| 作品と話 | `works/` | GET /works、GET /works/{id}、GET /works/{id}/members、GET /works/{id}/progress | POST /works、add_volume・add_episode・update_episode（締切）・set_member（招く・外す） |
| 企画 | `plan/` | GET /works/{id}、GET /works/{id}/ai-involvement | set_work_plan（変えた項目だけ）・set_work_settings（決めごと・入稿の設定。preferences は全体を送るので、今の値に混ぜて送る）・set_ai_involvement、POST /works/{id}/plan/extract-characters（人物を抜き出す） |
| 構成 | `structure/` | GET /works/{id}、GET /works/{id}/progress、GET /works/{id}/review-records | add_page・set_removed・assign_page・reorder_pages・add_spread・set_removed（spread）・update_page（page_kind・color_mode・dpi・nombre_display） |
| 設定資料 | `materials/` | GET /works/{id}（material_entries）、GET /works/{id}/images/{id}/thumbnail?size= | POST /works/{id}/images（絵を置く。持ち込んだ絵は利用規約の要点が要る）、add_material_entry・update_material_entry・decide_material_proposal（AIの案を採る・捨てる）・set_removed |
| 書き出し | `export/` | GET /works/{id}、GET /works/{id}/review-records、GET /works/{id}/exports/{run}、GET …/files/{name} | POST /works/{id}/preflight（先に確かめる）、POST /works/{id}/exports、update_page（color_mode） |
| 生成サービス | `services/` | 管理者：GET /services。参加者：GET /works/{id}/services（GET /services が 403 なら参加者の表示にする） | POST /services、PATCH /services/{id}（休ませる・住所・同時の数・予算・送り方・利用規約の要点）、PUT /routes/{process} |
| 取り込み | `import/` | GET /works/{id}、GET /works/{id}/current-app-imports/{report_id}（`?report=` で開き直す） | POST /works/{id}/episodes/{eid}/current-app-imports（ファイル・絵の出どころ・持ち込んだ絵の利用規約） |
| 翻訳 | `translation/` | GET /works/{id}（ページ・コマ・文字の並び）、GET /works/{id}/translations?language=、GET /works/{id}/review-records | set_text_translation（足す・変える）・set_text_translation_removed（抜く） |
| 確認 | `review/` | GET /works/{id}、GET /works/{id}/review-records | set_review_status（出す・決める。取り消しは reverts_record_id） |

画面ごとの振る舞い：
- 作品と話：話は巻ごとに並べ、話ごとに確認の状態の帯・数・確認待ちのページ（確認の画面へのリンク）・締切の見込みを出す。見込みの出し方はサーバーの計算のままで、当たるかは未検証。
- 企画：決めごと（題・媒体・読む向き・文字の向き・判型・ページの寸法・作品の言語）と入稿の設定（印刷・2階調・ノンブル・組版。作品の preferences。`V3サーバーの土台.md` 3.6）を折りたためる組で出す。AIの関与（4択）もここで選ぶ。
- 構成：ページを並べ、確認の状態・ページの種類・色・見開き・締切に遅れる見込みの印を付ける。選んだページを前後へ動かす・次のページと見開きにする・外す・抜く・ページの設定・割り当て。
- 設定資料：人物・場所・小物・その他に分けて探せる一覧と、選んだ物の中身（名前・特徴・メモ・絵・服・生成の設定（見た目の指示・入れない指示・seed・LoRA・参照の絵））。AIが足した案は採るか捨てるかを選ぶ。
- 書き出し：ページを選び、ファイル（PNG・PDF・PSD）・見開き（選んだページに見開きがあるときだけ送る）・言語・解像度を決める。先に「確かめる」（preflight）を押し、選び直したら確かめ直すまで書き出せない。止まる問題があっても書き出しは押せる（サーバーが止める）。書き出しの段（順番待ち・書き出している・できた・失敗）を 1.5 秒ごとに読み、できたファイルを保存する。
- 生成サービス：処理ごとの送り先を表で選ぶ（今の送り先の作業と手を引き継いで PUT する）。組（安い・良い・手元・API）は、送れる先（つながっている・休ませていない）から並びを計算して見せてから当てる。つなぎ先ごとのカードで休ませる・住所・送り方・予算・利用規約の要点を直す。受けられる処理は読むだけ。
- 取り込み：作品のページの寸法（page_spec）が無いと取り込めない（企画へのリンクを出す）。報告は元のページごとに、そのまま入れた・形を変えて入れた・入れられなかった・要らないで絞れる（最初は形を変えた物と入れられなかった物だけ）。
- 翻訳：言語を入れると（`?lang=` と localStorage の `v3.lang`）、ページごとに元の文字と訳文を左右に並べる（狭い幅では上下）。訳文・向き・大きさを直して「残す」。訳の無い文字だけに絞れる。作品の言語が決まっていない・作品の言語を選んだときは訳せない理由を出す。
- 確認：今の状態から移れる先だけをボタンにする（下書き→確認に出す、確認待ち→承認する・直しを頼む・引っ込める、直しが要る→直して出し直す、承認→開け直す）。直しを頼むにはコメントが要る。記録は新しい順で、最後の記録だけ取り消せる。誰が押せるかはサーバーが決め、断られたら理由を知らせに出す。

## 4. 試験と画面の写し

- `v3/web/test/screens_ui.mjs`：本物のサーバーに作品・巻・話・ページ・コマ・文字・参加者・設定資料（絵 1 枚）・訳文・確認の記録・つなぎ先と送り先を足し、9 画面を Playwright で通す。利用者は作者・編集者・翻訳者・管理者の 4 人。
  ```
  uv run python -m v3server.admin_command_line grant-admin scr-admin   # v3/server で、1回だけ
  V3_WEB=http://127.0.0.1:8771/web/ SHOTS=v3/web/screenshots \
  NODE_PATH=/opt/node22/lib/node_modules PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers node v3/web/test/screens_ui.mjs
  ```
- 写し：`v3/web/screenshots/01_works.png` 〜 `12_review.png`（1枚 1MB 未満。試験が大きさも確かめる）。
- 模擬（本物でない所）は書き出しだけ。名前に `mock` を付けた写し（06）がそれ。
  - 入稿前の確かめ（POST /works/{id}/preflight）は、原稿として出す形を合わせた後（2026-10-08）に本物の口へ替えた。試験の作品には入稿の設定が無いので、その問題と「企画で直す」が出る（05）。
  - POST /works/{id}/exports と進み具合・ファイル：本物は Temporal の作業者で書き出す。この環境では共有の Temporal に流さないので差し替えた。
- 本物で通したもの：作品と話・企画・構成・設定資料（絵を置く）・生成サービス（管理者・参加者）・取り込み（`v3/server/tests/fixtures/current_app_project_4pages.lz4` を第2話へ）・翻訳（翻訳者が訳文を足す）・確認（編集者が承認する・コメント無しの直しの依頼が止まる）。
- 試していないもの（未検証）：原稿として出す形の操作（ページの並べ替え・見開き・ページの設定・入稿の設定を残す）は、サーバーには合わせたが、画面からはまだ通していない。人物を抜き出す（LLM が要る）。原稿の画面・工程の画面へのリンクの先（別に作っている）。
