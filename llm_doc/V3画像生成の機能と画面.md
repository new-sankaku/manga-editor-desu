# V3画像生成の機能と画面

V3サーバー（`v3/server/`）の画像生成の処理と、それを使う画面（`v3/web/`）。
AIが描いた絵と人が描いた絵を、どちらの向きにも行き来させる。AIの答えはどれも候補で、人が選んで採用し、採用した後も人の手で直せる。

元にした調査は `llm_doc/V3調査/画像生成の機能の調査.md`。サーバーの土台（操作の窓口・順番待ち・権限）は `llm_doc/V3サーバーの土台.md`、ファイルの置き場は `llm_doc/V3サーバーのファイル構成.md`。

---

## 1. 処理の一覧

処理は `generation_queue/image_process_registry.py` の `SPECS` に1件ずつ並ぶ。画面の処理の一覧・入力欄・道具は、全部ここから来る。

| 処理 | 画面の名前 | 元の絵 | 囲んだ範囲 | 画面の道具 | 組み立て（`comfy_graphs/`） | 絵のモデルの設定 |
|---|---|---|---|---|---|---|
| `text_to_image` | 文から作る | 使わない | 使わない | なし | `text_to_image_graph.build_text_to_image_process` | `DiffusionSettings` |
| `image_to_image` | 絵から作り直す | 要る | 使わない | なし | `image_to_image_graph.build_image_to_image` | `DiffusionSettings` |
| `variation` | 似た別案 | 要る | 使わない | なし | 同上（変える強さの初めの値が小さい） | `DiffusionSettings` |
| `inpaint` | 囲んで直す | 要る | 要る | 囲む | `inpaint_graph.build_inpaint` | `DiffusionSettings` |
| `outpaint` | 描き足す | 要る | 使わない | 広げる枠 | `outpaint_graph.build_outpaint`（中は `build_inpaint`） | `DiffusionSettings` |
| `instruction_edit` | 指示で直す | 要る | どちらでも | 囲む | `instruction_edit_graph.build_instruction_edit` | `EditSettings` |

どれも AI の作業の種類は `drawing`、関わり方は `propose`（候補を出すだけ）。`known_processes.py` は `SPECS` から作るので、ここに足せば AI の関わりの確認と出どころの記録にも入る。

### 1.1 処理を足すとき

1. 引数のモデル（pydantic）を作る。欄ごとに `_f()` で見出しと画面の印（2章）を付ける
2. 下ごしらえの関数（`PrepIn → PrepOut`）を書くか、今ある物（`_prep_plain`・`_prep_inpaint`・`_prep_outpaint`・`_prep_edit`）を使う
3. ComfyUI のグラフを組む関数を `comfy_graphs/` に書く
4. `SPECS` に1行足す

画面・口・順番待ち・出どころの記録は変えない。`test_image_processes.py` が、全部の処理について、引数の初めの値でグラフが組めること・入力欄の印がそろっていることを確かめる。

### 1.2 つなぎ先ごとの中身

どのモデルを使うかは、つなぎ先と処理の組（`service_processes`）の `comfy_graph_settings` に持つ（移行 0008）。`PUT /services/{id}/processes/{process}` で入れ、`parse_settings` が処理の設定のモデルで確かめる。正しくなければ受けない。

- `DiffusionSettings`：モデル（1つのファイル `checkpoint` か、分かれた3つ `separate`）・LoRA・手数などの既定・`native_long_side`（モデルが得意な長い辺の画素）・`controlnet_name`（形の指定に使う ControlNet。無ければ `null` で、形の指定を頼むと断る）
- `EditSettings`：Qwen-Image-Edit-2511 の UNET・文の読み手・VAE・LoRA・`shift`・`megapixels`・手数などの既定

送る側（`service_senders/comfyui_sender.py`）は、依頼に処理の名前があれば、その組の設定と依頼の引数でグラフを組んで送る。

## 2. 引数と入力欄

画面は `GET /works/{id}/image-processes` で、処理ごとの説明と引数の JSON Schema（`params_schema`）を受け取り、そこから入力欄を作る（`v3/web/js/schema_form.js`）。欄の形は次の印で決める。

| 印 | 中身 |
|---|---|
| `x-group` | まとまり。「基本」はいつも開いて先に出す。処理の `open_groups` にあるまとまりも開いて出す（描き足すの「広げる」）。ほかは畳んで出す |
| `x-initial` | 初めの値 |
| `x-widget` | `textarea`・`number`・`slider`・`select`・`check` |
| `x-labels` | 選ぶ欄の見出し |
| `x-unit` | 数の単位 |
| `x-presets` | よく使う値のボタン（見出し → 値）。似た別案の「少し」「大きく」 |

手数（`steps`）と文の効き（`cfg`）は空にできる。空ならつなぎ先の設定の値を使う。

主な引数：

- 共通（文を使う処理）：このコマの指示・入れないもの
- 形の指定（`_Controlled`）：使わない・線画・落書き・骨格・奥行き、形の効き、効かせる所（終わり）、白地に黒い線（反転して渡す）
- 囲んで直す：境目をなじませる（差分拡散）・変える強さ（0.75）・広げる（6px）・境目のぼかし（8px）・描き方（元の絵から描く／範囲を消してから描く）・囲んだ所だけ大きくして直す（余白 32px）
- 描き足す：広げ方（画素で・mm で・コマの枠まで）・左上右下・広げた所の下塗り（端を伸ばす・折り返す・灰色）・境目のぼかし（16px）
- 指示で直す：直す指示・変える強さ（1.0）・囲んだ範囲の広げる・ぼかし・余白（64px）
- 似た別案：変える強さ（初め 0.3。ボタンで 0.3／0.55）

数値の初めの値は、今のアプリと調査の値を元にしたもの。漫画の絵でどれが良いかは未検証。

## 3. 絵とマスクの下ごしらえ

依頼を受けるとき（`generation_queue/image_process_preparation.py`）に、numpy と Pillow でマスクと絵を作り、`image_files` に置いてから順番待ちに入れる。ComfyUI の側は読んで使うだけ。

### 3.1 囲んだ範囲（`image_process_inputs.redraw_mask`）

順番は **0.5 で白黒にする → 広げる → ぼかす（外側へだけ） → 人の手の範囲を引く**。

- 調査の順は「広げる → ぼかす → 人の範囲を引く → 白黒にする」。ここでは最後に白黒にしない。ぼかしの幅を、元の画素となじませる所（3.2）と差分拡散の強さの差として使うため。代わりに、ぼかしは外側へだけ広げ、範囲の中はちょうど 1 のままにする。これで調査の「マスクの値が 1 に届かないと描き直しが効かない」問題（Stabilize Mask と同じ）は起きない。人の手の範囲はちょうど 0
- 人の手の範囲は最後に引くので、ぼかしが人の範囲へにじむことは無い
- 画面のマスクは透明の上に塗った PNG。サーバーは 赤 × 不透明度 を読む

### 3.2 ComfyUI の側（どの処理も同じ部品。`comfy_graphs/source_and_masks.py`）

- 絵とマスクは名前の付いた `LoadImage`（`source`・`redraw_mask`・`protected_mask`・`control`）で受ける。送る側がそこに上げたファイルの名前を入れる（`ai-verification.md` 1.1 の原因A を避ける）
- マスクは `ImageToMask` の赤のチャンネルで読む（同 原因B）
- マスクの拡大縮小は bilinear。lanczos は値が 0〜1 の外へはみ出す
- 描いた絵をモデルの大きさ（8 の倍数）から元の大きさへ戻し、描き直す範囲のマスクで元の絵の上に重ね（`ImageCompositeMasked`）、最後に人の手の範囲を元の画素で貼り戻す。これで、囲んだ外と人の手の範囲の画素は元の絵と1つも変わらない（実機で確かめた。7章）
- 差分拡散は標準の `DifferentialDiffusion`（強さ 1.0）。入れると、マスクの値の分だけ描き直す強さが変わる

### 3.3 囲んだ所だけ大きくして直す（`only_masked`）

調査の crop-and-stitch を、標準のノード（`ImageCrop`・`CropMask`・`ImageScale`・`ImageCompositeMasked`）だけで組んだ。範囲を囲む四角に余白を足して切り出し、長い辺を `native_long_side` へ拡大して描き、縮めて元の位置へ重ねる。GPL のカスタムノードは使わない。

### 3.4 描き足す（`_prep_outpaint`）

- mm とコマの枠までは、依頼を受ける前に画素へ直す（`resolve_outpaint`）。比は今の置き場（切り抜きの画素と置き場の mm）から決める。回転・傾き・反転のある置き場では断る。端数は切り上げ
- 広げた分の外側を埋めて（端を伸ばす・折り返す・灰色）、広げた所を描き直す範囲にする。範囲は、広げた辺から内側へぼかしの幅だけ 1→0 へ下げる
- 人の手の範囲は広げた絵の上の位置へずらす
- できた絵の `details.geometry` に、元の絵の画素から新しい絵の画素への写し方（`scale`・`offset`）を残す。採用すると、コマの置き場をこの写し方で移すので、元の絵はページの同じ位置に残り、広げた分がコマの枠の外へ出る（`operations/image_placement_carry.py`）
- 調査の「LaMa で先に埋めてから描く」は入れていない（9章）

### 3.5 指示で直す（`_prep_edit`・`build_instruction_edit`）

- モデルは Qwen-Image-Edit-2511（Apache-2.0）。`TextEncodeQwenImageEditPlus` で元の絵を文と一緒に渡す
- 囲んでいれば、範囲を囲む四角に余白を足して切り出し、`ImageScaleToTotalPixels` で `megapixels` に合わせて描き、切り出した大きさへ戻して、描き直す範囲のマスクでその位置に重ねる。囲まなければ絵の全体
- 最後に人の手の範囲を元の画素で貼り戻す
- 調査の色ずれの直し（Color Match）は、標準のノードに無いので入れていない（9章）

### 3.6 似た別案

候補ごとに seed を変える。「この絵に近い物」は、その絵を元にした弱い img2img を、2つの強さ（少し 0.3・大きく 0.55）から選ぶ（調査の Fooocus の Vary と同じ形）。値は未検証。

### 3.7 形の指定（ControlNet）

ControlNet Union（xinsir の union promax、Apache-2.0）を、どの処理にも付けられる入力にした。線画は `canny/lineart/anime_lineart/mlsd`、落書きは `hed/pidi/scribble/ted`、骨格は `openpose`、奥行きは `depth` の種類で渡す（`SetUnionControlNetType`）。つなぎ先の設定に `controlnet_name` が無ければ断る。CPU の実機に ControlNet のモデルが無いので、実機では未検証。

### 3.8 絵の中の ComfyUI の情報を消す

ComfyUI は PNG の文字のチャンクにプロンプトとワークフローを書く。生成した絵を受け取るとき（`image_intake.strip_png_text`）に文字のチャンクだけを消す。解像度と色の情報は残す。

### 3.9 使わないモデル（利用条件）

調査の通り、商用に使えない物は入れていない：Qwen-Image 2.1・Flux Fill・FLUX.1 Kontext dev・MAT・RMBG-2.0・NoobAI の ControlNet と inpaint のモデル。

## 4. 候補と版

### 4.1 候補の組

1回の依頼で、枚数分の依頼（順番待ちの1件ずつ）を作り、同じ `candidate_set_id` を付ける。seed は乱数（`secrets.randbelow(2**32)`）か、固定（入れた値から1ずつ増やす）。

できた絵は `panel_art` の役で登録し、`details` に処理・引数・頼んだときの引数・seed・候補の組・つなぎ先・写し方を残す。

### 4.2 採用・取り消し・却下

- 採用（`adopt_image`）：コマの絵（か層の絵）をその絵にする。中ではコマを変える操作を使うので、取り消すと前の絵に戻る。人だけができる（AIは候補を出すだけ）。却下した絵は採用できない
- 却下（`set_image_discarded`）：候補に印を付ける。消さない。取り消せる。コマで使っている絵は却下できない（移行 0008 の `image_files.discarded`）
- 採用したとき、元の絵と新しい絵の写し方（4.3）でコマの置き場を移す

### 4.3 置き場を移す（`operations/image_placement_carry.py`）

絵の `based_on_image_id` をたどって共通の祖先を見つけ、写し方を合わせて、今の置き場を新しい絵へ移す。大きさが同じなら写し方はそのまま。描き足しで辺に接していた切り抜きは、新しい絵の辺まで伸ばす。つながりが無い絵（文から作る）は、コマの枠を覆うように置く。

### 4.4 版

コマに置いたことのある絵（生成でない絵・今の絵の祖先・採用の出来事で置いた絵）を、新しい順に並べる。「戻す」は採用と同じ操作なので取り消せる。

## 5. 口

| 口 | 中身 |
|---|---|
| `GET /works` | 見てよい作品の一覧 |
| `GET /works/{id}/image-processes` | 処理ごとの説明・`params_schema`・`open_groups`・送り先・選べるつなぎ先（送ってよいか・休みか・設定の要約） |
| `POST /works/{id}/panels/{panel_id}/generate` | 頼む。`process`・`params`・`count`（1〜8）・`seed_mode`・`seed`・`source_image_id`・`mask`（`png_base64` か `region_px`）・`control`（`png_base64` か `image_id`）・`service_id` |
| `GET /works/{id}/panels/{panel_id}/candidates` | 候補の組。依頼ごとの状態・seed・つなぎ先・設定、絵ごとの却下の印、人の手の範囲のマスクの URL |
| `GET /works/{id}/jobs/{job_id}/protected-mask` | その依頼に渡した人の手の範囲（できた絵の上の位置） |
| `GET /works/{id}/panels/{panel_id}/versions` | 版の一覧（`current` の印） |
| `GET /works/{id}/images/{image_id}/thumbnail?size=` | 小さい絵（PNG） |
| `GET /works/{id}/images/{image_id}/protected-mask` | その絵の人の手の範囲（白が範囲）。見出し `X-V3-Region-Count` に数 |

採用・却下・取り消しは操作の窓口（`POST /works/{id}/ops`・`POST /works/{id}/events/{event_id}/undo`）。ペンの線と画素の消しゴムは今ある口（`add_pen_strokes`・`POST /works/{id}/layers/{layer_id}/stroke-cache`・`POST /works/{id}/panels/{panel_id}/erase-pixels`）。

`service_id` で送り先を替えるときも、作品の送ってよい先の確認は通る。つなぎ先がその処理の設定を持っていなければ断る。

## 6. 画面（`v3/web/`）

サーバーが `/web` で出す（`http_app_factory.py` の `StaticFiles`）。同じ口から出すので、`file://` の制約はかからない。

| ファイル | 中身 |
|---|---|
| `index.html` | 枠組み。上に作品・ページ・コマ、左に絵と道具、右に「頼む」「候補」「版」のタブ |
| `css/app.css` | 色・部品。画面の試作（`v3poc/screen/index.html`）の明るい方の色と部品の名前に合わせた。暗い色の組は持たない |
| `js/api.js` | 口を呼ぶ。利用者は `X-V3-User` で送る（右上の欄。ブラウザに覚える） |
| `js/schema_form.js` | 引数の JSON Schema から入力欄を作る（2章） |
| `js/stage.js` | 絵を見て、囲む・広げる枠・ペン・消しゴムを扱う（fabric.js） |
| `js/app.js` | 選ぶ・頼む・進み具合・候補・比べる・採用・却下・版・取り消し |
| `vendor/fabric-7.4.0/` | fabric.js 7.4.0（MIT）。npm の包みから取った `fabric.min.js` と LICENSE |
| `vendor/lucide-0.468.0/` | Lucide 0.468.0（ISC）。アイコン。画面の試作と同じ |
| `test/image_generation_ui.mjs` | Playwright で画面を通す（7章） |

React は使わない（利用者の決まり）。ライブラリは手元に置き、実行時に CDN を使わない。

### 6.1 道具

- 見る：ドラッグで動かす。ホイールで拡大
- 囲んで頼む：筆・消す・投げ縄・多角形（最初の点を押すかダブルクリックか Enter で閉じる。Esc でやめる）・四角。太さ、1つ戻す（囲みだけの戻し。30回まで）、反転、全部、消す、見せる・隠す
- 描き足す：絵の周りの枠の辺と角を動かす。動かすと引数が「画素で」になり、左上右下に量が入る。入力欄に mm で入れても枠が動く（コマの置き場から画素に直す）。コマの枠までは頼むときにサーバーが決める
- ペン：鉛筆で人の手の層に描く（太さ 0.3／0.6／1.2mm）。線は `add_pen_strokes` で mm の点として残し、画面が線から控えの絵を描いて `stroke-cache` で上げる。この層が無ければ先に作る
- 消しゴム：コマの絵の画素を消す（`erase-pixels`）。消した所は人の手の範囲になる
- 取り消す・やり直す：この画面で行った操作（採用・却下・版を戻す・ペン・消しゴム）を、出来事の取り消しで戻す。やり直しは取り消しの出来事を取り消す。ペンは「層を作る・線を足す・控えを上げる」をまとめて1回として戻す
- キー：V・M・O・P・E で道具、Ctrl+Z／Ctrl+Shift+Z

### 6.2 囲んだ範囲は画素で持つ

囲んだ範囲は fabric の図形ではなく、絵と同じ大きさの canvas に塗る。送るのはこの canvas なので、見えている物と送る物が同じになる。人の手の範囲（橙）は塗るたびに canvas から引くので、塗れない。

前と違う絵を出すと（採用・版を戻す・版を見る）、囲んだ範囲は消す。前の絵の上で塗った物を別の絵に重ねないため。囲む処理（`mask` が `none` でない処理）を選んでいるときだけ、囲んだ範囲を見せる。

### 6.3 進み具合

ポーリング（1.5秒ごとに候補の口を読む）。EventSource は見出し（`X-V3-User`）を付けられないため。作っている依頼が無くなったら止める。読めなかった回も、作っている物が残っていれば続ける。「止める」は組の中の待っている依頼を全部止める。

### 6.4 候補

組ごとに、新しい順に並べる。絵ごとに、つなぎ先・モデル・seed・強さ（変える強さ・描き直しの強さ）、「採用中」「却下」「人の手そのまま」の印を出す。小さい絵の上に、その依頼に渡した人の手の範囲を橙で重ねる（できた絵の上の位置。その所は元の画素のまま）。

- 採用・却下（却下をやめる）
- 似た別案 少し／大きく：その絵を元に、似た別案の処理を頼む（頼んだ文は組の物を使う）
- この設定でもう一度：その組の処理と頼んだときの引数を入力欄に戻す。囲んだ範囲は戻さない
- 比べる：小さい絵を押して2枚まで選ぶ。1枚なら今の絵と比べる。並べる・重ねて動かす（境目を左右に動かす）

### 6.5 動かし方

1章の手順（`V3サーバーの土台.md`）でサーバーと作業者を動かし、`http://127.0.0.1:8000/web/` を開いて、右上に利用者の名前を入れる。つなぎ先と処理の設定は管理者が `PUT /services/{id}/processes/{process}` で入れる（`comfy_graph_settings`）。

## 8. 決めたことと理由

- **進み具合はポーリング。** EventSource は見出しを付けられない。ログインが入って cookie になれば SSE にできる
- **絵は fetch して blob の URL にする。** `<img src>` は見出しを付けられないため
- **囲んだ範囲は画素の canvas。** 送る物と見えている物を同じにするため（6.2）
- **ぼかしは外側へだけ、最後に白黒にしない。** 3.1
- **指示で直すのモデルは Qwen-Image-Edit-2511。** 調査で商用に使えて、ComfyUI の標準のノードで動く物。FLUX.2 klein 4B も候補だが、まだ組んでいない（9章）
- **ペンは鉛筆だけ。** 控えの絵は画面が描く決まり（`http_routes/pen_stroke_routes.py`）。この画面に今のアプリの12種の筆を移していないので、ほかの筆の線がある層では控えを作らずに断る
- **移行の番号を 0008 にした。** 同じ時期に別の作業で 0007（出来事に判断待ちを残す）が入ったため

## 9. 未検証・まだ作っていないもの

- **指示で直す・形の指定（ControlNet）は実機で流していない。** CPU の ComfyUI に Qwen-Image-Edit-2511 と ControlNet Union のモデルが無い。グラフはふりの ComfyUI と組み立ての試験でだけ確かめた。Qwen-Image-Edit-2511 が 12GB の GPU に入るかも未検証
- **絵の質は見ていない。** 実機は SD1.5・128px・2手で、画素が守られるかだけを見た。強さ・ぼかし・余白の初めの値が漫画の絵に合うかは未検証
- **色ずれの直し**（調査の Color Match）：標準のノードに無い（comfyui-inpaint-nodes などのカスタムノードが要る）。入れていない
- **描き足す前に LaMa で埋める**（Apache-2.0）：同じくカスタムノードが要る。入れていない
- **FLUX.2 klein 4B の指示で直す**：手元の ComfyUI に必要なノード（`ReferenceLatent`・`EmptyFlux2LatentImage`・`Flux2Scheduler`・`CFGGuider`・`SamplerCustomAdvanced`）はあるが、グラフをまだ組んでいない
- **Fooocus の inpaint と、union promax の inpaint の使い方**：入れていない
- **試作 p26（指示で直す）の作り直し**：試作は商用に使えないモデルで行ったので、Qwen-Image-Edit-2511 で作り直しが要る
- 描き直す範囲の値を ComfyUI の側でもう一度白黒にする（ThresholdMask）必要があるかは未検証。今は bilinear で縮めた後の値をそのまま使う
- 画面：ペンの鉛筆の見え方が今のアプリの筆（fabric の PencilBrush）と同じかは未検証。層の置き場に回転などがあると、画面には出さない
- 画面：形の指定の絵は、ファイルを選んで渡すだけ。コマの絵の上で描く道具は無い
- 画面：スマートフォンの幅では、右の欄が下に回る（900px 以下）。触って使えるかは未検証
