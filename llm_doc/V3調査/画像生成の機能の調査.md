今の画像生成の道具（ComfyUI とその追加ノード、Krita AI Diffusion、InvokeAI、Forge・reForge、Fooocus、SwarmUI、NovelAI、CLIP STUDIO PAINT）が持つ機能のうち、漫画を作るのに要るものを、V3 に入れるかどうかの順に並べた。

読む前に:
- 部品とモデルの利用条件の多くは `画像生成の部品と利用条件の調査.md`（2026-09-30）にある。ここでは繰り返さず「部品の調査 2.1」のように指す。
- 試作の結果は `../V3検証の結果.md`、処理と送り先の表は `../V3細部の決めごと.md` 4.7、人の手の範囲は同 10.2、作画の中身の設定は同 12章、サーバーの受け口は `../V3人とAIの受け渡し.md` 6章にある。
- 出典は、配布元の README・モデルの説明（model card）・LICENSE の原文・公式の説明書を、コマンドで直接取って読んだ。検索の要約だけで決めたものは無い（CLIP STUDIO の検索の要約は、元の公式ページを開いて確かめた）。
- 2025年より前の記述は「古い可能性あり」と書いた。
- 法的な判断ではない。商用に使う前に、各配布元の条件の原文を読む必要がある。

- 商用に使う予定は無い。利用条件が非商用でも、入れない理由にしない。この文書の「商用」の列と「入れない（商用不可）」は、判断の材料として残すだけにする。

2. **Krita AI Diffusion が Illustrious 向けに揃えている制御・参照・インペイントは、ほぼ NoobAI 系で、商用に使えない。** Krita の一覧（`models.json`）では、Illustrious 用の線画・落書き・奥行き・骨格・ぼかし戻し・インペイント・参照が、NoobAI 由来（Eugeoter、Laxhar、Acly/NoobAI-Inpainting、r3gm/noob-ipa）になっている(*10)(*71)。NoobAI の商用禁止は部品の調査 2.1。Krita の作りを手本にするときは、部品を差し替える必要がある。
3. **ぼかしたマスクは、囲んだ範囲の外にはみ出す。** Krita はマスクを少し広げ、端をぼかし、さらに外側に貼り合わせ用の範囲を取る(*2)。ComfyUI の切り出しと貼り戻しのノードも、広げる・ぼかす値を持つ(*11)。人の手の範囲を「広げる・ぼかす前」に引くと、はみ出した分が人の範囲に掛かる。人の範囲は、広げる・ぼかすの**後**に引き、最後に元の画素で貼り戻す必要がある（10.2、p05 の結果）。
4. **指示で直すモデルは、絵全体を描き直す。** p26 では、出力が32の倍数に丸められて位置がずれた。指示で直すときも、囲んだ範囲だけを切り出して渡し、戻すときに人の範囲を貼り戻す形にする必要がある。

## 第2部 機能ごと

### 2.1 インペイントの質

**何か**：囲んだ所だけを描き直す。境目が目立つ、周りと色がずれる、人の線まで変わる、の3つが問題になる。

**どの道具にあるか**
- Krita AI Diffusion：選択範囲で「Fill・Expand・Add Content・Remove Content・Replace Background」を選ぶ(*2)。中では、マスクを少し広げ、端をぼかした「描き直すマスク」と、外側に広い「貼り合わせのマスク」の2つを作る(*2)。周りの絵をどれだけ一緒に渡すか（context）も決める(*2)。
  - 「Seamless」を切ると、選んだ所を1枚の絵として描く。Krita の説明書は、漫画のページの中の1コマを描くときの例として挙げている(*2)。コマの絵を描く V3 の形に近い。
- ComfyUI-Inpaint-CropAndStitch：囲んだ所の周りを切り出し、モデルの得意な大きさに直して描き、元に戻す。「It does not modify the unmasked part of the image, not even passing it through VAE encode and decode」(*11)。広げる（`mask_expand_pixels`）、ぼかして貼る（`mask_blend_pixels`）、外へ広げる（`extend_for_outpainting`）の値を持つ(*11)。2026-01-09 に GPU で30〜100倍速くなった（作者の記載）(*11)。
- comfyui-inpaint-nodes（Krita の作者）：Fooocus のインペイント用の差分、LaMa・MAT、余白の埋め方（灰色・周りの色・ぼかし）、Expand Mask・Shrink Mask・Stabilize Mask、Color Match(*12)。
  - Stabilize Mask は、0.9999… のような値でマスクが効かない問題を避ける、と書いてある(*12)。人の範囲のマスクを作るときにも同じ問題が起きうる（未検証）。
- 差分拡散（Differential Diffusion）：マスクの濃さを、画素ごとの描き直す強さとして使う。ComfyUI 標準のノード（`DifferentialDiffusion`）になっている(*13)(*16)。論文は2023年（古い可能性あり）。
- ComfyUI 標準：GrowMask・FeatherMask・MaskComposite（multiply・add・subtract・and・or・xor）・ThresholdMask(*14)。

**必要なもの**：ComfyUI 標準のノードと、上の2つの追加ノード。どれも SDXL で VRAM は足りる。

**商用**：ComfyUI 本体と追加ノードの多くは GPL-3.0（*11 *12 *15）。V3 は ComfyUI を別のプロセスとして呼ぶだけで、配らない。GPL の義務が V3 のコードに及ぶかは法的判断で、ここでは決めない（未確認）。

**V3 への入れ方**
- 処理「囲んで直す」の手順（`protected_redraw_graph.py`）に、次の順で入れる。
  1. 人が囲んだ範囲を広げる・ぼかす。
  2. その後で、人の手の範囲を引く（MaskComposite の subtract）。
  3. 切り出して描く。
  4. 元の大きさに戻して貼る。
  5. 最後に、人の手の範囲を元の画素で貼り戻す。
- 3 と 4 だけで外は変わらない、と CropAndStitch の作者は書く(*11)。ただし、貼るときのぼかし（`mask_blend_pixels`）が人の範囲に掛かるかは未検証。5 は p05 の結果から外さない。
- 画面：「囲んで頼む」の道具に「広げる」「ぼかす」「周りをどれだけ見せるか」の3つの値を置く。既定は Krita の考え方（広げるは少し、ぼかしは囲んだ大きさの割合）に倣う。数値は未検証。
- 「人の範囲に掛かったので、そこは描き直していない」ことを、候補の絵の上に印で見せる。人が囲んだ範囲と人の手の範囲が重なったときに、黙って小さくすると、人は効かなかった理由が分からない。

### 2.3 アウトペイント

**何か**：絵の外を描き足す。横長・縦長のコマに合わせるとき、斜めのコマの角を埋めるときに使う。

**どの道具にあるか**

- ComfyUI 標準の ImagePadForOutpaint：上下左右に足す画素数と、ぼかしの幅（既定40）(*15)。
- CropAndStitch の `extend_for_outpainting`(*11)。
- comfyui-inpaint-nodes：余白を先に埋める（LaMa・MAT、周りの色を流す Telea・Navier-Stokes）(*12)。
- FLUX.2 klein 4B 用のアウトペイントの LoRA（fal、Apache-2.0、2026-01）。Krita が使う(*10)(*71)。
- Fooocus の Up・Down・Left・Right(*20)。

**条件**：LaMa は Apache-2.0、MAT は CC BY-NC 4.0（*70）。Krita の「inpaint-default-all」は MAT（Acly/MAT、CC BY-NC 4.0）なので、Krita の既定のままでは商用に使えない(*10)(*71)。

**V3 への入れ方**
- p14 で、余白のあるコマと横長・縦長への合わせ方を調べてある（`V3検証の結果.md` 1-32〜1-34）。そこで決めた形に、「LaMa で埋めてからインペイント」を手の1つとして足す。
- 置き場所は「囲んで直す」の一種。画面では、コマの枠を絵より大きくしたときに、「外へ足す」の案を出す。勝手には描かない（AIの関与の4択に従う）。

### 2.7 LoRA の管理と呼び出しの言葉

- Civitai の口：`GET /api/v1/model-versions/by-hash/{hash}` で、手元のファイルの SHA256 からモデルを特定できる。100件まとめて引ける。返事に `trainedWords`（呼び出しの言葉）がある(*57)。
- kohya の sd-scripts で学習した LoRA は、ファイルの中に `ss_tag_frequency`（学習に使ったタグの数）と `ss_base_model_version` を持つ(*58)。呼び出しの言葉が分からない LoRA でも、ここから候補を出せる。
- Civitai の商用可否の表示は掲載者が付けるもので、元の条件と食い違う例がある（部品の調査 1章）。
- **V3 での置き場所**：つなぎ先のカードの「入っているもの」で、LoRA ごとに、元のモデル（SDXL・Illustrious など）、呼び出しの言葉、条件を出す。元のモデルが合わない LoRA は選べなくする（Krita も「Extensions between different base models are not compatible」と書く(*5)）。

### 2.17 出どころの記録と条件

- EU の AI 法 50条2項：画像などを作る AI の提供者は、出力を「marked in a machine-readable format and detectable as artificially generated or manipulated」にする。普通の編集を助けるだけのもの、入力を大きく変えないものは外れる(*67)。2026-08-02 より前に出した仕組みは、2026-12-02 までに合わせる（解説サイトの日程）(*67)。V3 が EU で使われる・EU に向けて出すかは決めていない。
- C2PA（Content Credentials）：作った物の出どころを、署名した記録として絵に付ける。AI で作った物は `digitalSourceType` に IPTC の `trainedAlgorithmicMedia` を入れる(*68)。2026-10 時点で仕様は 2.4 まである(*68)。c2pa-python は Apache-2.0 と MIT(*69)。PSD に付けられるかは未検証。
- FLUX.1 dev の条件は、出力に AI で作ったことを示すよう求め、内容の確認か内容の絞り込みを求める(*21)。商用に使わない場合でも V3 の書き出しに関わる。
- **V3 での置き場所**：書き出しの画面。どのコマを AI が作り、どのコマを人が直したかは、正本に既にある（受け渡し 2.4・2.5）。それを C2PA の記録に写す形にする。後で。

### 2.18 NovelAI と CLIP STUDIO PAINT

- NovelAI：
  - 「You ... retain all rights and ownership of your Content」(*64)。
  - 禁止事項に「Enable or allow others to use the Services or Software using your account information」「Copy, modify, host, sublicense, or resell the Services」がある(*64)。
  - V3 で複数の人が1つの NovelAI のアカウントを使う形は、これに当たる恐れがある。1人が自分のアカウントのキーを入れて自分で使う形なら合うかは、未確認。
  - インペイントの強さ、「Focused Inpainting」（囲んだ所に絞る）がある(*63)。
- CLIP STUDIO PAINT：
  - 2022-12-02 に「CLIP STUDIO PAINTへ画像生成AI機能を搭載しないことといたしました」(*65)。
  - 自動彩色は、データをサーバーに上げて処理する（公式 TIPS、2020年で古い可能性あり）(*66)。
  - 外のアプリから呼ぶ口は見つけていない（未確認）。V3 とのつながりは PSD の行き来（p52・p59）だけ。

| 指示で直す | 囲んだ所の切り出し、大きさの戻し、人の範囲の貼り戻し、色のずれの戻し | p26 の位置ずれと外の変化 |

| 候補の画面 | 候補ごとに、送り先・モデル・seed・強さ・人の範囲で描き直さなかった所の印を出す | 人が効かなかった理由を分かるように |
