# V3サーバーのファイル構成

作成 2026-10-08、コミット cd5dc91 の状態に合わせた。同じ日に、c0b6a13（人とAIの受け渡し）と、その次の作業（人が直す道具・仕上げ・書き出し。移行 0006）と、画像生成の機能と画面（移行 0008）で足したファイルを加えた。試作（`v3poc/`）で確かめた処理をサーバー（`v3/`）に移すときの、ディレクトリとファイルの置き方。動かし方と既製品は `llm_doc/V3サーバーの土台.md`。

## 決まり
- 1ファイル1000行以下。超えそうになったら、役目で分ける。
- ファイル名は中身がそのまま分かる名前にする。`models.py`・`utils.py`・`common.py`・`helpers.py`・`app.py` のような一般的な名前は付けない。
- 疎結合にする。依存は下の「層」の向きにだけ流れる。
  - 計算だけの部品（ネームの形・コマ割りの計算・検査・問いの文・ComfyUIの手順の組み立て・層の分け方）は、データベース・HTTP・Temporal を import しない。入力と出力はネームの形（`name_structure/`）と、ただの辞書・画像の配列だけ。データベースを立てずに試験できる。
  - LLM・ComfyUI・検出器を呼ぶ処理は、計算だけの部品に「呼ぶ関数」を引数で渡す。計算だけの部品は呼び先を知らない。
  - 正本を変えるのは操作の窓口（`operations/`）だけ。
- 検出器（imgutils）と PSD の書き出し（ag-psd、Node）は、使う言語と依存が大きく違うので、サーバーとは別のプロセスにする（`v3/detector_server/`、`v3/psd_writer/`）。サーバーからは HTTP か標準入出力で呼ぶ。
- 効かなかった手（試作で効かないと分かったもの）は移さない。対象：線画の制御でラフを渡す（p08）、参照画像の部品 IP-Adapter（p09・p17・p18）、初めだけ縮小して作る（p14）、否定の言葉でフキダシを防ぐ（p22）、光の向きの言葉（p25）、枠の大きさの閾値で距離を決める（p44）、完成画像から顔の隠れを検出する（p47）、NSFW の判定器（p35）。
- MagiV2 は別のプロジェクトで扱うので、ここには移さない（利用者の指示 2026-10-08）。
- 閾値は試作の小さな標本から出した目安なので、コードに書かない。`Threshold` の表から読む（`V3ハーネス設計.md` 7章）。

## 層（上が下を使う。逆は無い）
1. `http_routes/`（画面から呼ぶ口）・`queue_worker_main.py`（作業者）
2. `operations/`（操作の窓口）・`generation_queue/`（順番待ち）・`service_senders/`（呼び先への送信）
3. `canonical_tables/`（正本の表）・`lock_rules.py`・`openfga_permissions.py`・`image_file_storage.py`（絵の置き場）
4. 計算だけの部品：`panel_layout/`・`name_checks/`・`llm_questions/`・`judge_procedures/`・`comfy_graphs/`・`layer_split/`・`background_scene3d/`・`print_export/`（`export_runner.py`・`export_workflow.py` は正本を読むので2の層）・`hand_tools/`・`name_import/`・`current_app_import/`
5. `name_structure/`（ネームの形。どこからも使う。何も import しない）
