## 2. 不具合と、決まりに反している所（最初に直す）
1. 古い操作を取り消すと、後から他の人が同じ所に入れた変更も、知らせずに消える（点検1 8-1、点検5 4-1）。
   - 直した（2026-10-08、48f4afc）。出来事に変えた項目を残し、後の出来事が同じ項目を変えていれば取り消さずに 409 と記録（`undo_conflicts`）を返す。別の項目なら取り消せる。`V3サーバーの土台.md` 3.0。
   - 決めごと 16章の「後から保存した側を別の版にする」は、版の仕組みが無いので作っていない（どちらの値も消さない所まで）。版を入れるのは正本の作り直しになる（点検1 8-2・8-3 と一緒に決める）。
2. 筆圧が取れないとき 0.5 を作って正本に保存している。fallback 禁止に反する（点検3 2.1）。
   - 直した（2026-10-08、48f4afc）。画面は PointerEvent で受け、`pointerType` が `pen` のときだけ筆圧を数で持つ。マウス・指は筆圧を null、描いた機器を `pointer_type` に持つ（移行 0010）。1本の中で null と数を混ぜない・マウスで筆圧ありは断る。筆圧の無い線は筆の太さのまま一定の太さで描く（`hand_tools/vector_strokes.py`・`v3/web/js/pen_render.js`）。指（touch）の筆圧の扱いは実機で確かめていない（未検証）。`V3画像生成の機能と画面.md`・`V3サーバーの土台.md` 3.4。
3. 見る権限だけで絵を上げられ、権限を確かめる前にファイルを置く。大きさの上限も無い（点検5 3-1・3-2）。
   - 直した（2026-10-08、48f4afc）。権限とロックをファイルを書く前に確かめる。一時ファイルに少しずつ写す。本体のバイト数・画素数・PSD の層の数の上限を設定（既定値なし）で持つ。PSD を戻す口も同じ。`V3サーバーの土台.md` 3.3。
   - ペンの口（`pen_stroke_routes.py`）の絵のアップロードは、ほかの作業と重なるので触っていない。上限は共通の所でかかるが、権限を先に確かめる順と丸ごと読む所は残る。
4. PostgreSQL・OpenFGA・Temporal・LiteLLM が認証なしで外に開いている（点検5 5-4）。
   - 直した（2026-10-08、48f4afc）。どの口も 127.0.0.1 にだけ開く。OpenFGA は事前共有鍵が要る。`V3サーバーの土台.md` 1章。PostgreSQL の合言葉は `v3` のまま（本番の形で入れ替える）。
5. 生成の途中で作業者が落ちると、二重に送り、二重に登録する（点検5 4-2）。
   - 直した（2026-10-08、48f4afc）。送る前に鍵と費用の取り置きを持つ記録を確定し、受け取った答えを残してから、登録と依頼の終わりを1回で確定する。答えがあれば送り直さない。予算はつなぎ先の行を取ってから数える。`V3サーバーの土台.md` 7章。
   - 送った後、答えを残す前に落ちたときは、送ったか分からない記録（`unknown`）を残して送り直す（決めごと 4.5 の時間切れと同じ）。ここは二重に送りうる。
6. 囲んでいる最中に Ctrl+Z を押しても囲みが戻らない。コマを替えても取り消しの記録が残り、見ていないコマが戻る。消しゴムを使うと囲みが知らせなしに消える（点検3 2.6）。
   - 直した（2026-10-08、48f4afc）。取り消しの記録をコマごとに1つにし、囲みを塗ったのもサーバーの操作も新しい順に Ctrl+Z で戻す。コマを替えると囲みはそのコマの分として取っておき、戻ると出し直す。消しゴム・採用の後も、絵の大きさが同じなら囲みは残る。大きさが変わって囲みを捨てるときは知らせる。`V3画像生成の機能と画面.md`。

2章の外で、同じときに直したもの：
- `GET /services` が誰にでも住所と費用を見せる（点検5 5-1）・`location=local` の申告だけで送り先の制限を素通りする（点検5 5-2）。一覧は管理者だけにし、参加者には `GET /works/{id}/services` で要る項目だけを返す。手元と言えるのは、直接送る送り手で住所がこの機械のものだけ（`V3サーバーの土台.md` 5章・6章）。48f4afc。

## 3. 必須（重さ順のまとめ）
### 原稿として出せない所（点検1）
- 見開き：書き出しも、見開き1枚の絵も扱えない。
- 本の構成：ノンブル・ページの並べ替え・ページの種類が無い。
- 色と解像度：ページごとの色の種類（白黒2階調・グレー・カラー）と解像度が無い。2階調の書き出しが流れにつながっていない。
- 縦書きの組版：禁則・縦中横・約物の向き・自動の改行が無い。行間は定数で、文字の一部だけ書式を変えられない。
- 翻訳：言語ごとの文字を持てず、翻訳者は何も直せない。
- フキダシ：しっぽを書き出しで描かない。
- トーン：グラデトーンが網点にならない。
- ペン：線の絵をブラウザに任せ、書き出しに足りる解像度かを確かめない。
- 分業：承認・工程・進捗が無い。
- 入稿：入稿前の確かめが無い。
### AIの本体（点検2）
- 工程の進行役と、作業1回の流れ（切り出し→文脈を組む→作業→検査→評価→判断待ち）が無い。
- 設定資料とネームが作画に渡らない。設定資料は保存するだけで、生成で読まれない。
- 検出器と評価役が、作画の流れにつながっていない。
- 判断待ちの一覧が1本になっていない。止まった依頼・検査の失敗・候補・古くなったものは入らない。
- 上流を変えたとき、古くなったものを伝えない。
- 閾値に初めの値が無いので、新しい作品では検査が全部「閾値未設定」になる。
- LLM の問いは10種あるが、口につながっているのは2種だけ。
### 画面（点検3・点検4）
- 原稿の画面（コマ枠・文字・フキダシ・トーン・層・ナイフ）、企画・構成・設定資料・書き出し・生成サービスの画面が無い。
- ペンは1本ごとに通信10回・約1.5秒かかる。消しゴムは1本7.5秒かかる。
  - 直した（2026-10-08、48f4afc）。描いた物は先に画面に出し、保存は後ろで1つずつ送る（ペン1本の保存は通信1回・約0.3秒）。控えの絵は描き終えて4秒経ったとき・頼む前・コマを替える前に1回だけ上げる。消しゴムは消した所を先に画面に出す。消しゴムの保存はサーバーで約3〜4秒（4960×7016 の PNG を作り直す所）、その後の人の手の範囲の読み込みに2〜3秒かかるのは残る。数字は `V3画像生成の機能と画面.md` 6.6。
- 今のアプリのプロジェクトを V3 に移す道が無い。
### 本番（点検5）
- ログインが無い。
- 本番の形（アプリのコンテナ・Temporal の本番構成・TLS）が無い。
- 絵の置き場が S3 互換になっていない。DB・OpenFGA・絵を揃えて取る控えと、戻す手順が無い。
